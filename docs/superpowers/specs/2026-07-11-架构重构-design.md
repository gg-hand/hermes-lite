## 2. 兼容性约束

以下三项在深度重写中必须保持兼容:

1. **API 契约兼容** — /chat、/chat/stream、/schedules、/config、/approvals 等 30+ 端点的请求/响应格式不变,前端无需改动
2. **config.yaml 格式兼容** — 字段结构和 ${ENV_VAR} 占位符机制不变,用户配置文件无需迁移
3. **数据文件格式兼容** — chroma 向量库、sqlite 日志、history_buffer、schedules.yaml 等格式不变,升级后数据不丢失

桌面端接口可调整。

## 3. 整体架构:模块化单体 + DI 容器

### 3.1 依赖方向

```
routes/  →  container  →  agent.Orchestrator  →  各领域模块
(表现层)     (DI 容器)       (瘦编排器)           (llm/memory/tasks/...)
                                                  ↓
                                              storage/infra
```

核心规则:外层依赖内层,领域模块之间不直接导入,只通过容器注入的接口通信。

### 3.2 10 个领域模块

| 模块 | 职责 | 可热重载 |
|------|------|----------|
| agent/ | Agent 执行(Orchestrator、SessionManager、ContextBuilder、SkillManager、CronIsolator、MessagePersistence、ReactLoop、tools/) | 否 |
| llm/ | LLM 客户端(LLMClient、ReasoningProfiles、Prompts) | ✅ 重建 client |
| memory/ | 记忆系统(SignalPool、Consolidation、ContextManager、Retrieval、MemoryMd、Decay) | 部分(阈值) |
| tasks/ | 调度工作流(Scheduler、TaskManager、TodoList、workflow/) | 部分(enabled) |
| storage/ | 存储层(ChromaStore、SqliteLog、HistoryBuffer) | ✅ 连接迁移 |
| security/ | 权限策略(PolicyEngine、ApprovalStore) | ✅ 重载规则 |

## 4. DI 容器设计

### 4.1 容器结构

```python
class Container:
    """轻量 DI 容器:组件单例 + 工厂延迟创建 + 热重载重建。"""

    def __init__(self, config: dict):
        self._config = config
        self._instances: dict[str, Any] = {}       # 单例缓存
        self._factories: dict[str, Factory] = {}    # 工厂注册
        self._deps: dict[str, list[str]] = {}       # 依赖图(谁依赖谁)
        self._lock = threading.RLock()              # 保护热重载并发
```

### 4.2 组件注册

```python
container.register(
    name="llm_client",
    factory=lambda c: LLMClient(c.config["llm"]),
    deps=[],
    hot_reloadable=True,
)

container.register(
    name="orchestrator",
    factory=lambda c: Orchestrator(
        llm_client=c.get("llm_client"),
        policy_engine=c.get("policy_engine"),
        chroma_store=c.get("chroma_store"),
    ),
    deps=["llm_client", "policy_engine", "chroma_store"],
    hot_reloadable=False,  # 本身不热重载,但依赖变更时级联重建
)
```

### 4.3 热重载流程

```python
def reload(self, changed_sections: set[str], new_config: dict):
    """1. 映射配置段→受影响组件  2. 拓扑排序计算级联  3. 逐个重建"""
    with self._lock:
        self._config = new_config
        directly_affected = self._map_config_to_components(changed_sections)
        to_rebuild = self._topo_sort_dependents(directly_affected)

        old_instances = {}
        for name in to_rebuild:
            old_instances[name] = self._instances.pop(name, None)
            self._instances[name] = self._factories[name](self)

        # 异步关闭旧实例
        for name, old in old_instances.items():
            if old and hasattr(old, "close"):
                threading.Thread(target=lambda o=old: self._safe_close(o, name), daemon=True).start()
```

### 4.4 配置段→组件映射

```python
CONFIG_TO_COMPONENTS = {
    "llm":        ["llm_client"],
    "security":   ["policy_engine"],
    "storage":    ["chroma_store", "sqlite_log", "history_buffer"],
    "memory":     [],      # 阈值类,直接改属性不重建
    "tasks":      [],      # schedules.enabled 直接改属性
    "server":     [],      # 端口,需重启(不热重载)
}
```

### 4.5 并发安全策略

| 场景 | 处理方式 |
|------|----------|
| 热重载期间新请求到达 | RLock 保护,新请求获取重建后的新实例 |
| 正在处理的旧请求 | 持有旧实例引用(Python 引用计数),完成后自然释放 |
| factory 内部获取依赖 | RLock 可重入,不会死锁 |
| 旧实例 close() 失败 | 守护线程异步执行,失败仅记日志 |

### 4.6 组件接口约定

可热重载组件必须实现:
- `__init__(self, config, ...)` — 从配置创建实例
- `close(self)` — 释放资源(关闭连接、停止线程、flush 数据)

## 8. 热重载具体流程

### 8.1 LLM 热重载

触发:config.yaml 中 llm 段变更(provider/model/api_key/base_url/timeout)

1. PUT /config 写盘 + 校验
2. 容器映射: {"llm"} → ["llm_client"]
3. 拓扑排序级联: llm_client → orchestrator
4. 重建 llm_client(创建新 AsyncOpenAI/AsyncAnthropic + 新 HTTP 连接池)
5. 重建 orchestrator(注入新 llm_client,其他依赖不变)
6. 异步关闭旧 llm_client(关闭旧 HTTP 连接池)

边界处理:
- 正在进行的流式聊天 → 旧 Orchestrator 继续处理,流结束后 GC 释放
- 新聊天请求 → 获取新 Orchestrator(新 llm_client)

### 8.2 安全权限热重载

触发:config.yaml 中 security 段变更(rules/enabled/timeout)

1. 容器映射: {"security"} → ["policy_engine"]
2. 拓扑排序: policy_engine → orchestrator
3. 重建 PolicyEngine(重新加载 rules、重建黑/白名单)
4. 重建 orchestrator(注入新 policy_engine)
5. 旧 policy_engine 无状态资源,无需 close

改进:当前 rules/enabled 变更需重启,新架构下可热重载。

### 8.3 存储路径热重载(最复杂)

触发:config.yaml 中 storage 段变更

1. 容器映射: {"storage"} → ["chroma_store", "sqlite_log", "history_buffer"]
2. 拓扑排序级联:
   - chroma_store → signal_pool, consolidation, retrieval, orchestrator
   - sqlite_log → metrics_store
   - history_buffer → orchestrator, context_manager
3. 重建顺序: [底层存储] → [中间层] → [orchestrator]
4. 异步关闭旧存储(flush + 关闭连接)

数据迁移策略:
- 新路径不存在 → 创建空库,旧数据保留在原位置
- 新路径已有数据 → 直接打开使用
- 不做自动数据迁移

UX 保护:前端修改存储路径时弹窗提示。

### 8.4 不可热重载项

| 配置 | 原因 | 处理 |
|------|------|------|
| server.port | uvicorn socket 绑定 | needs_restart=True |
| server.host | 同上 | 同上 |

### 8.5 热重载响应格式

```json
{
  "status": "saved",
  "message": "配置已保存。LLM 客户端已热重载,2 个组件已级联重建。",
  "needs_restart": false,
  "reloaded": ["llm_client", "orchestrator"],
  "skipped": []
}
```

## 9. 错误处理统一

### 9.1 异常体系

```
ToolError(基类)
  ├── ToolNotFoundError      # 工具不存在
  ├── ToolExecutionError     # 执行失败
  ├── ToolPermissionDenied   # 权限拒绝
  └── ToolTimeoutError       # 超时

ConfigError(基类)
  ├── ConfigValidationError  # schema 校验失败(400)
  └── ConfigReloadError      # 热重载重建失败(500)
```

### 9.2 全局异常处理

- app.py 注册全局异常处理器,捕获基类返回结构化错误
- 路由层不再写 try/except
- 组件内部抛具体异常,不返回错误码

```json
{"error": "tool_not_found", "message": "工具 xxx 不存在", "detail": {...}}
```
