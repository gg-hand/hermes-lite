## 一、验证目标

本方案在阶段 5（N=2 双 worker 集成测试 + 30 分钟性能采集）已通过的基础上，将验证范围扩展到 N=3 / 5 / 10 与跨机部署，目标是：

- **可用性**：N=3 / 5 / 10 部署下系统连续运行不崩溃，无消息丢失。
- **故障切换**：单实例 Director 死亡 → 30s 内通过选举（`Election.run()`）由其他实例接管。
- **广播正确性**：Director 通过 `A2AClient.call_all_endpoints`（`asyncio.gather` 并发 N 端点）广播的消息，全部 N 个 worker 均能收到。
- **性能可控**：
  - A2A HTTP 调用 99 分位延迟 < 1s（N≤10 同机）。
  - 协作消息端到端延迟 < 30s（N≤5）/ < 60s（N=10，含 LLM 限流串行）。
  - audit.jsonl 增长速率 < 10/分钟。
- **资源限流有效**：LLM 并发不超过 `asyncio.Semaphore(N)` 上限；A2A 调用并发不超过 `Semaphore(10)`。
- **跨机鲁棒性**：200ms 延迟 + 5% 丢包下重试不雪崩，选举不误触发。
- **瓶颈识别**：定位 N 增大时第一个失效的子系统（A2A / 文件锁 / LLM / director 主循环 / audit I/O / watchdog），为后续是否引入 Redis 提供数据依据。

## 二、验证矩阵

| N | 部署形态 | 验证时长 | 关键指标 | 验收标准 | 优先级 |
|---|---|---|---|---|---|
| 2 | 同机 | 30 分钟 | a2a_p99 / audit_growth / director_unreachable / sample_success_rate | 已通过（阶段 5） | — |
| 3 | 同机 | 60 分钟 | 上述 + election_total / election_success_rate | 选举 failover 30s 内成功，无消息丢失 | P0 |
| 5 | 同机 | 60 分钟 | 上述 + broadcast_latency_p99 / llm_concurrent_in_flight | 100 条广播全到达，端到端 < 30s | P1 |
| 10 | 同机 | 120 分钟 | 上述 + a2a_retry_total / file_lock_contention_count | a2a_p99 < 1s，LLM 并发受限，端到端 < 60s | P2 |
| 3 | 跨机器 | 60 分钟 | 上述 + 网络抖动场景 a2a_retry_total | 重试不雪崩（< 10/min），选举不误触发 | P2 |

> 矩阵设计原则：从 N=2 已验证状态出发，每次只增加一个维度（N +1 / 引入新指标 / 切换部署形态），便于在失败时快速定位是规模问题还是新指标问题。

### 3.1 同机多端口部署（N=3 示例）

基于现有 `config-a2a-1.yaml` / `config-a2a-2.yaml` 风格扩展。每个 worker 实例需独立配置：
- `server.port`：8000 / 8001 / 8002
- `multiagent.blackboard_dir`：`data/blackboard_a2a_1` / `_2` / `_3`（方案 Y：各实例独立 blackboard）
- `multiagent.worker.agent_id`：`teagent-lu` / `teagent-liu-2` / `teagent-liu-3`

### 3.2 跨机器部署（多机 N=3 示例）

方案 Y 天然支持跨机：每个 worker 部署在独立机器，`a2a.remote_endpoints` 指向其他机器的 host:port。

| 机器 | 实例 | agent_id | 监听 | blackboard_dir |
|---|---|---|---|---|
| host1 | worker-1 | teagent-lu | host1:8000 | data/blackboard_a2a_1 |
| host2 | worker-2 | teagent-liu-2 | host2:8000 | data/blackboard_a2a_2 |
| host3 | worker-3 | teagent-liu-3 | host3:8000 | data/blackboard_a2a_3 |

#### 3.2.1 跨机 config 片段（worker-1 视角）

```yaml
a2a:
  enabled: true
  remote_endpoints:
  - name: worker-2
    url: http://host2:8000
  - name: worker-3
    url: http://host3:8000
  retry_count: 2            # 跨机网络抖动，保留 2 次重试
  timeout_seconds: 5        # 跨机适当放宽
multiagent:
  blackboard_dir: data/blackboard_a2a_1
  worker:
    agent_id: teagent-lu
server:
  host: 0.0.0.0            # 必须监听非 loopback
  port: 8000
```

#### 3.2.2 跨机部署注意事项

1. **网络可达性**：三台机器互相可访问 8000 端口（防火墙放行）；建议同子网，避免公网 RTT 抖动。
2. **时钟同步**：选举依赖 epoch + 字典序，但 audit/heartbeat 时间戳仍需 NTP 同步（偏差 < 1s）。
3. **无共享存储**：方案 Y 各实例独立 blackboard，不依赖 NFS/SMB，避免跨机文件锁不可靠问题。
4. **环境变量**：每台机器各自的 `.env` 配置 `LLM_MAIN_API_KEY` 等。
5. **状态同步**：Director 通过 A2A `read_director_md` / `read_status_json` 查询其他实例，关键状态变更通过 A2A 广播（最终一致性）。

### 3.3 启动脚本

#### 3.3.1 start_n_workers.ps1（Windows，N 可参数化）

```powershell
# 启动 N 个本地 worker 服务脚本（同机多端口，方案 Y：各实例独立 blackboard）
# 用法：
#   powershell -ExecutionPolicy Bypass -File start_n_workers.ps1 -N 3
#   powershell -ExecutionPolicy Bypass -File start_n_workers.ps1 -N 5
#   powershell -ExecutionPolicy Bypass -File start_n_workers.ps1 -N 10
# 前提：
#   1. 已生成 config-a2a-1.yaml ~ config-a2a-N.yaml（用 generate_n_configs.ps1）
#   2. .env 已配置 LLM_MAIN_API_KEY 等

param(
    [int]$N = 3,
    [int]$BasePort = 8000
)

$ErrorActionPreference = "Stop"
$root = Split-Path -Parent $MyInvocation.MyCommand.Path
Set-Location $root

if ($N -lt 2 -or $N -gt 10) {
    Write-Error "N 必须在 2..10 范围内，当前 N=$N"
    exit 1
}

Write-Host "=== 启动 $N 个本地 Worker（方案 Y：A2A 同步，各实例独立 blackboard） ===" -ForegroundColor Cyan

# 检查 .env
if (-not (Test-Path "$root\.env")) {
    Write-Host "[警告] .env 不存在，LLM 调用可能失败" -ForegroundColor Yellow
}

# 创建必要的 data 目录
for ($i = 1; $i -le $N; $i++) {
    $dirs = @(
        "data/blackboard_a2a_$i/agents",
        "data/blackboard_a2a_$i/audit",
        "data/blackboard_a2a_$i/locks",
        "data/blackboard_a2a_$i/tasks",
        "data/blackboard_a2a_$i/schemas",
        "data/blackboard_a2a_$i/snapshots",
        "data/uploads$i",
        "data/history$i"
    )
    foreach ($d in $dirs) {
        if (-not (Test-Path "$root\$d")) {
            New-Item -ItemType Directory -Path "$root\$d" -Force | Out-Null
        }
    }
}

# 启动 N 个实例
$pids = @()
for ($i = 1; $i -le $N; $i++) {
    $port = $BasePort + $i - 1
    $config = "config-a2a-$i.yaml"
    if (-not (Test-Path "$root\$config")) {
        Write-Error "配置文件不存在：$config，请先运行 generate_n_configs.ps1 -N $N"
        exit 1
    }
    Write-Host "[$i/$N] 启动 worker-$i (端口 $port, config=$config)" -ForegroundColor Green
    $proc = Start-Process -FilePath "python" `
        -ArgumentList "-m", "teage_liu" `
        -WorkingDirectory $root `
        -PassThru -WindowStyle Normal `
        -Environment @{TEAGE_CONFIG=$config}
    $pids += $proc.Id
    Write-Host "      PID=$($proc.Id)"
    Start-Sleep -Seconds 2   # 错开启动，避免端口/文件竞争
}

# 记录 PID
$pids -join "`n" | Out-File "$root\.n_workers.pid" -Encoding utf8
Write-Host ""
Write-Host "=== $N 个 worker 已启动 ===" -ForegroundColor Cyan
Write-Host "端口范围：$BasePort .. $($BasePort + $N - 1)"
Write-Host "PID 列表已写入 .n_workers.pid"
Write-Host "停止：Get-Content .n_workers.pid | ForEach-Object { Stop-Process -Id $_ -Force }"
Write-Host ""
Write-Host "按任意键退出此脚本（服务继续运行）..."
$null = $Host.UI.RawUI.ReadKey("NoEcho,IncludeKeyDown")
```

#### 3.3.2 generate_n_configs.ps1（生成 N 份配置）

```powershell
# 基于模板 config-a2a-1.yaml 生成 N 份配置文件
# 用法：powershell -ExecutionPolicy Bypass -File generate_n_configs.ps1 -N 5
param(
    [int]$N = 3,
    [int]$BasePort = 8000
)

$root = Split-Path -Parent $MyInvocation.MyCommand.Path
$template = Get-Content "$root\config-a2a-1.yaml" -Raw

for ($i = 1; $i -le $N; $i++) {
    $port = $BasePort + $i - 1
    $content = $template
    # 端口
    $content = $content -replace 'port: 8000', "port: $port"
    # agent_id
    if ($i -eq 1) {
        $agentId = "teagent-lu"
    } else {
        $agentId = "teagent-liu-$i"
    }
    $content = $content -replace 'agent_id: teagent-lu', "agent_id: $agentId"
    # blackboard_dir
    $content = $content -replace 'blackboard_dir: data/blackboard_a2a_1', "blackboard_dir: data/blackboard_a2a_$i"
    # sqlite / chroma / history / uploads / memory / audit 后缀
    if ($i -eq 1) {
        $suffix = ""
    } else {
        $suffix = "$i"
    }
    $content = $content -replace 'sqlite_path: data/sessions\.db', "sqlite_path: data/sessions$suffix.db"
    $content = $content -replace 'chroma_path: data/chroma\b', "chroma_path: data/chroma$suffix"
    $content = $content -replace 'memory_md_path: data/memory\.md', "memory_md_path: data/memory$suffix.md"
    $content = $content -replace 'persistence_dir: data/history\b', "persistence_dir: data/history$suffix"
    $content = $content -replace 'upload_dir: data/uploads\b', "upload_dir: data/uploads$suffix"
    $content = $content -replace 'audit_log_path: data/audit\.jsonl', "audit_log_path: data/audit$suffix.jsonl"
    # _config_path
    $content = $content -replace '_config_path: config-a2a-1\.yaml', "_config_path: config-a2a-$i.yaml"

    # 重写 remote_endpoints 段：列出除自己外所有 N-1 个对端
    $endpoints = ""
    for ($j = 1; $j -le $N; $j++) {
        if ($j -eq $i) { continue }
        $peerPort = $BasePort + $j - 1
        $endpoints += "  - name: worker-$j`r`n    url: http://localhost:$peerPort`r`n"
    }
    # 用正则替换 remote_endpoints 段（从 "remote_endpoints:" 到下一个顶层键）
    $content = $content -replace '(?s)  remote_endpoints:.*?\n([a-z])', "  remote_endpoints:`r`n$endpoints`$1"

    $outPath = "$root\config-a2a-$i.yaml"
    Set-Content -Path $outPath -Value $content -Encoding utf8
    Write-Host "[生成] $outPath (port=$port, agent_id=$agentId, peers=$($N - 1))" -ForegroundColor Green
}
Write-Host "完成：$N 份配置已生成"
```

#### 3.3.3 start_n_workers.sh（Linux/macOS，跨机用）

```bash
#!/usr/bin/env bash

echo "[启动] config=$TEAGE_CONFIG blackboard_dir=$BB_DIR"
```

## 四、性能指标采集扩展

### 4.1 现有指标（已采集，N=2 验证用）

`scripts/collect_perf_metrics.py` 当前采集 4 项指标，阈值已对齐验收清单：

| 指标 | 类型 | 阈值 | 采集方式 |
|---|---|---|---|
| `a2a_p99_ms` / `p95_ms` / `p50_ms` | summary | < 1000 / 500 / — | 采样 `worker2/api/multiagent/director/status` 延迟，百分位插值 |
| `audit_growth_per_min` | summary | < 10 | 统计 `audit.jsonl` 行数差 / 采样时长 |
| `director_unreachable_count` | counter | == 0 | director/status 请求失败或 running=false 时 +1 |
| `sample_success_rate` | gauge | ≥ 0.95 | 采样成功次数 / 总采样次数 |

### 4.2 新增指标（N-Worker 场景，N≥3）

| 指标 | 类型 | 阈值（N=10） | 说明 | 采集来源 |
|---|---|---|---|---|
| `election_total` | counter | ≤ 1/小时 | 选举触发次数 | director/status 新增字段 `election_count` |
| `election_success_rate` | gauge | == 1.0 | 选举成功率（胜者成功启动 director） | director/status `election_won` / `election_total` |
| `broadcast_latency_p99_ms` | summary | < 2000 | call_all_endpoints 全部对端返回的 99 分位 | A2AClient 内埋点 |
| `llm_concurrent_in_flight` | gauge | ≤ Semaphore(N) | 当前并发 LLM 调用数 | worker_adapter `_llm_lock` / Semaphore 统计 |
| `llm_semaphore_saturation` | gauge | < 0.8 | LLM 信号量饱和度（in_flight / max） | 同上 |
| `file_lock_contention_count` | counter | < 5/min | 跨进程文件锁争用次数 | FileLock.acquire 超时或等待 > 100ms 时 +1 |
| `agent_card_sync_lag_ms` | summary | < 5000 | 跨实例 agent_card 同步延迟 | A2A `read_status_json` 对比本地时间戳 |
| `a2a_retry_total` | counter | < 5/min | A2A 调用重试总次数 | a2a_client `call_method` 重试路径埋点 |
| `director_tick_age_seconds` | gauge | < 5 | director 主循环 tick 年龄 | director/status `last_tick_age` |

#### 4.3.2 采集逻辑扩展（伪代码）

```python
def collect_n(duration, workers: list[str], audit_paths: list[Path], ...):
    metrics = {
        "n": len(workers),
        "workers": workers,
        "samples": [],                 # 每次采样快照（含 N 维度）
        "a2a_latencies_ms_per_worker": {w: [] for w in workers},  # 按 worker 切片
        "broadcast_latencies_ms": [],  # 新增：广播延迟
        "election_events": [],         # 新增：选举事件
        "director_pid_history": {w: [] for w in workers},  # pid 变化追踪
        "summary": {"per_worker": {}, "aggregate": {}},
    }

    while time.time() < end_time:
        snap = {"ts": _now_iso(), "per_worker": {}}
        for w in workers:
            # 1. director/status（含 election_count / last_tick_age 新字段）
            ok, data, lat = _http_get_json(f"{w}/api/multiagent/director/status")
            snap["per_worker"][w] = {"ok": ok, "latency_ms": lat, **data}
            if ok:
                metrics["a2a_latencies_ms_per_worker"][w].append(lat)
                # 检测选举事件
                if data.get("election_count", 0) > last_election_count.get(w, 0):
                    metrics["election_events"].append({"ts": _now_iso(), "worker": w})
                # 检测 pid 变化
                ...
        # 2. 采集 broadcast 延迟（主动探测：广播一条 marker，等所有 N 端可见）
        blat = _measure_broadcast_latency(workers, marker=f"probe-{int(time.time())}")
        metrics["broadcast_latencies_ms"].append(blat)
        # 3. audit 行数（所有 N 个）
        for i, ap in enumerate(audit_paths):
            snap["per_worker"][workers[i]]["audit_lines"] = _count_lines(ap)
        metrics["samples"].append(snap)
        time.sleep(sample_interval)

    # 汇总：per_worker + aggregate
    for w in workers:
        lats = metrics["a2a_latencies_ms_per_worker"][w]
        metrics["summary"]["per_worker"][w] = {
            "a2a_p99_ms": _percentile(lats, 0.99),
            "a2a_p95_ms": _percentile(lats, 0.95),
            "sample_count": len(lats),
        }
    all_lats = [l for lats in metrics["a2a_latencies_ms_per_worker"].values() for l in lats]
    metrics["summary"]["aggregate"] = {
        "a2a_p99_ms": _percentile(all_lats, 0.99),
        "broadcast_p99_ms": _percentile(metrics["broadcast_latencies_ms"], 0.99),
        "election_total": len(metrics["election_events"]),
    }
    return metrics
```

## 五、验证场景

### 5.1 场景 A：N=3 选举 failover

**目标**：验证单实例 Director 死亡后，30s 内其他实例通过 `Election.run()` 接管。

**前置**：
- 3 个 worker 已启动并完成初始选举（通过 `GET /api/multiagent/director/status` 确认仅一个 running=True）
- 等待 60s 让集群稳定

**步骤**：
1. 通过 `director/status` 找出当前 Director 所在实例（`running=True` 那个）及其 `pid`
2. 用 `taskkill /PID <pid> /T /F`（Windows）或 `kill -9 <pid>`（Linux）杀掉该子进程
3. 记录杀进程时刻 `t0`
4. 每 1s 轮询所有 3 个 worker 的 `director/status`
5. 断言：30s 内出现另一个实例 `running=True` 且 `pid` 与旧的不同
6. 断言：选举事件计数 `election_count` 至少 +1
7. 断言：广播一条 marker 消息，其他 2 个 worker 均能收到（无消息丢失）

**验收**：
- failover 时长 < 30s
- 选举成功率 = 100%
- 无双 Director（任意时刻只有一个 running=True）
- marker 消息在所有存活 worker 的 `messages` 端点可见

**伪代码**（扩展现有 `test_n_worker_collab.py`）：

```python
def test_n3_election_failover():
    workers = [f"http://localhost:800{i}" for i in range(3)]
    # 1. 找当前 director
    director_url, director_pid = _find_current_director(workers)
    # 2. 杀掉
    _kill_pid(director_pid)
    t0 = time.time()
    # 3. 轮询等待 failover
    deadline = t0 + 30
    while time.time() < deadline:
        time.sleep(1)
        running_workers = [_running_director(w) for w in workers if w != director_url]
        running_workers = [w for w in running_workers if w is not None]
        if len(running_workers) == 1:
            new_director = running_workers[0]
            assert new_director["pid"] != director_pid
            print(f"[failover-ok] {time.time() - t0:.1f}s 新 director={new_director}")
            return
        assert len(running_workers) == 0, f"出现双 Director: {running_workers}"
    pytest.fail(f"30s 内未完成选举 failover")
```

### 5.3 场景 C：N=10 LLM 限流

**目标**：验证 N=10 下并发协作消息触发的 LLM 调用受 `asyncio.Semaphore(N)` 限流，不超过上限。

3. 断言：任意时刻 `llm_concurrent_in_flight ≤ N`
4. 断言：`llm_semaphore_saturation < 0.8`（避免长期满载）
5. 断言：端到端延迟 < 60s（限流后串行处理，10 条 × 平均 5s/条 = 50s，留 20% 余量）

**验收**：
- LLM 并发不超过 `Semaphore(N)` 上限
- 无 LLM 调用超时（`stream_total_timeout=300s` 未触发）

**注意**：

### 5.4 场景 D：N=10 A2A 调用风暴

**目标**：验证 N=10 下 A2A HTTP 调用（`call_all_endpoints` 并发 9 个对端）不引发网络拥塞与重试雪崩。

4. 断言：
   - `a2a_p99_ms < 1000`（aggregate）
   - `a2a_retry_total < 5/min`

### 5.5 场景 E：跨机网络抖动

**目标**：验证跨机 N=3 部署在 200ms 延迟 + 5% 丢包下，A2A 重试不雪崩，选举不误触发。

**前置**：
- 3 台机器跨机部署，各自 worker 已启动

**验收**：
- 60 分钟内 a2a_retry_total < 10/min
- 无误触发选举
- 关闭抖动后 30s 内重试率恢复 < 1/min

**风险**：
- Windows `clumsy` 工具可能影响本机所有网络流量，建议在隔离 VM 中运行
- `tc` 需要 root 权限

## 六、性能瓶颈预测

基于代码逻辑推断的瓶颈点（按 N 增大时的恶化顺序排列）：

| 瓶颈点 | 触发 N | 表现 | 根因（代码位置） | 缓解措施 | 长期方案 |
|---|---|---|---|---|---|
| LLM 调用风暴 | N>3 | 端到端延迟陡升，`llm_concurrent_in_flight` 长期满载 | `worker_adapter._trigger_urgent_llm` 串行化（任务 2.3 的 `asyncio.Lock`）；N 个 worker 同时触发 → 排队 | `Semaphore(N)` 限流；N>10 时分桶 | LLM 调用结果缓存 + 增量上下文 |
| A2A HTTP 调用 | N>5 | `a2a_p99` 上升，`a2a_retry_total` 增加 | `a2a_client.call_all_endpoints` 并发 N-1 端点，无并发上限（`asyncio.gather` 无 Semaphore） | `call_all_endpoints` 内加 `Semaphore(10)`；连接池复用 | gRPC 替代 HTTP + 长连接 |
| 文件锁争用（同机） | N>3（同机） | `FileLock.acquire` 超时，`file_lock_contention_count` 上升 | `agent_card.md` 跨进程锁（任务 1.2 `portalocker.LOCK_EX`），N 个 worker 同时写同一共享文件 | 锁粒度细化（per-agent 文件锁）；批量写入 | N>10 时引入 Redis 分布式锁 |
| audit.jsonl I/O | N>5 | audit 增长速率逼近 10/min，I/O wait 上升 | `director_engine` 每次 trust_score_update / heartbeat 都写 audit.jsonl | 批量写入（攒 10 条 flush 一次）；分片 `audit_YYYYMMDD.jsonl` | 异步队列 + 单独 flush 线程 |
| watchdog 监听开销 | N>10 | 文件描述符耗尽，watchdog 自检降级为轮询 | `watchdog_watcher.py` 每实例一个 watcher，监听整个 blackboard_dir | 单 watcher + path filter（只监听 collaboration.md） | 共享 watcher 进程 |
| Director 主循环 | N>8 | `director_tick_age` 上升 > 5s | `director_engine._run_loop` 串行执行 6 个子任务（tick/heartbeat/turn/observe/flush/arbitrate） | 子任务并行化（`asyncio.gather`） | 拆分 director 为多协程 |
| 选举抖动 | N>5（网络抖动） | `election_total` 异常增长，频繁双 Director | `Election.run()` 基于 epoch + 字典序，无 lease 续约；网络抖动误判超时 | lease 30s 续约；quorum 选举 | Raft/Paxos（引入 etcd） |
| agent_card 同步延迟 | N>5 | `agent_card_sync_lag_ms` 上升，跨实例视图不一致 | 方案 Y 依赖 A2A `read_status_json` 拉取，无主动推送 | 改为 push 模式（状态变更即广播） | 引入发布订阅（Redis Pub/Sub） |

### 6.1 瓶颈触发时序图

```
N=2  ──────────────────────────────────────────── 已验证通过（阶段 5）
N=3  ─────── LLM 调用风暴可能触发（ Semaphore(N) 限流后可控 ）
```

### 6.2 缓解措施优先级

1. **P0（N=3 即需）**：LLM `Semaphore(N)` 限流（任务 2.3 已实现 `_llm_lock`，需升级为 Semaphore）

3. **P1（N=5 即需）**：audit.jsonl 批量写入（攒 10 条 flush）
4. **P2（N=10 即需）**：文件锁粒度细化（per-agent 锁文件）
5. **P2（N=10 即需）**：Director 子任务并行化
6. **P3（N>10 才需）**：Redis 分布式锁 + 发布订阅（本次不实现）

| B. 阶段 5.4c 后 | N=10 同机通过再测跨机 | 同机优先，跨机作为补充验证 |
| C. 暂不引入 | 仅同机验证 | 部署形态确定为同机 |

**推荐**：B。用户决策 6 为"同机/多机都可能"，但同机验证更易控制变量；跨机作为 P2 补充验证。若用户实际部署形态偏向多机，可提前到 A。

### 决策 3：性能瓶颈触发后是否立即引入 Redis

| 选项 | 触发条件 | 影响 |
|---|---|---|
| A. 立即引入 | 任意瓶颈触发即引入 Redis | 违背用户决策 5"暂不引入外部依赖" |
| B. 仅记录，不引入 | 记录瓶颈数据，不引入 Redis | 符合用户决策 5；瓶颈数据供未来决策 |
| C. N>10 才考虑 | 仅当验证 N>10 时引入 | 中规模 N≤10 不需要 Redis |

**推荐**：B + C 结合。本次验证范围内（N≤10）不引入 Redis，仅记录瓶颈数据；若未来需扩展到 N>10，再依据瓶颈数据决定是否引入 Redis 分布式锁 + 发布订阅。

### 决策 4：是否需要压力测试（N>10）验证降级路径

| 选项 | 内容 | 优点 | 缺点 |
|---|---|---|---|
| A. 需要 | 主动测 N=15/20，验证降级（如拒绝连接 / 限流熔断） | 提前发现上限 | 耗时；可能损坏数据 |
| B. 不需要 | 仅验证 N≤10 正常路径 | 聚焦目标；风险低 | 上限未知 |
| C. 仅模拟 | 用 mock 模拟 N=20 的 A2A 调用，不真起 20 进程 | 折中 | 真实性不足 |

**推荐**：B。用户决策 3 明确"中规模 N≤10"，本次验证聚焦该范围；N>10 的降级路径留待未来架构演进时验证。

### 决策 5：LLM 限流实现方式

| 选项 | 实现 | 适用 |
|---|---|---|
| A. asyncio.Lock（任务 2.3 已实现） | 完全串行 | N≤3 可接受 |
| B. asyncio.Semaphore(N) | 允许 N 个并发 | N≥5 推荐 |
| C. asyncio.Semaphore(N/2) | 保守限流 | LLM API 配额紧张时 |

**推荐**：B。N=5/10 时 Lock 完全串行会导致端到端延迟超标（10 条 × 5s = 50s，接近 60s 阈值）；Semaphore(N) 允许 N 个并发，但需结合 LLM API 实际配额调整。

### 决策 6：长采采样间隔

| 选项 | 间隔 | 采样数（60 分钟） | 优点 | 缺点 |
|---|---|---|---|---|
| A. 10s | 10s | 360 | 数据密集，易发现抖动 | 日志量大 |
| B. 30s（现有默认） | 30s | 120 | 平衡 | 可能漏掉短抖动 |
| C. 60s | 60s | 60 | 日志小 | 数据稀疏 |

**推荐**：B（30s，与现有 `collect_perf_metrics.py` 默认一致）。N=10 长采（120 分钟）可放宽到 30s；N=3 短验证（60 分钟）可收紧到 10s。

### 10.2 风险与回滚

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| N=10 同机端口/资源耗尽 | 中 | 启动失败 | 错开启动 2s；监控端口占用；N=10 前先验证 N=5 |

| 跨机网络抖动模拟影响其他服务 | 中 | 干扰同机其他进程 | 在隔离 VM 中运行；限定网络接口 |
| 选举算法在 N=10 下抖动 | 中 | 频繁双 Director | lease 30s 续约；quorum 选举（P3 长期方案） |
| 文件描述符耗尽（watchdog） | 低（N≤10） | watchdog 降级轮询 | 单 watcher + path filter |

**回滚预案**：
1. 立即 `Stop-Process` 所有 worker（`Get-Content .n_workers.pid | ForEach-Object { Stop-Process -Id $_ -Force }`）
2. 清理 blackboard 目录（`Remove-Item data/blackboard_a2a_* -Recurse -Force`）
3. 恢复 N=2 配置（`config-a2a-1.yaml` / `config-a2a-2.yaml` 已有备份）
4. 用 `start_dual_workers.ps1` 重启 N=2

### 10.4 术语表

| 术语 | 含义 |
|---|---|
| N | worker 实例数量 |
| Director | 集群唯一协调者角色（基于选举） |

| A2A | Agent-to-Agent，跨实例 JSON-RPC 通信 |

| lease | 选举租约，防止频繁切换 Director |
| quorum | 多数派，N/2+1 个实例同意才生效 |
