### 任务 3.2: stdio 绑定 + RemoteBranchAdapter ✅

**文件**: 新建 `teage_liu2/core/stdio.py`、`teage_liu2/core/remote_adapter.py`

- `StdioChannel`: spawn 子进程 + JSON 行协议双向帧读写 + **握手互报 `protocol_version`**（heartbeat 帧承载；协商收敛逻辑归阶段 4 evolution 域）+ 请求-响应匹配（v0.1.0 顺序约束）+ 心跳 + 优雅关闭（shutdown 帧 + 终止兜底 + Windows transport 显式清理）
- `RemoteBranchAdapter(Branch)`: 对 core 是普通扩展；11 钩子经 invoke_hook 转发（仅调用 `hooks_implemented` 声明的）；action dict → Action 值对象（make_action）；Injection/ToolDecision 还原；`invoke_tool` 轻量通道（tool_executor 声明者，免快照序列化，T-5）
- `dispatch_tool_call` 按 capabilities 分流: tool_executor 声明者走 invoke_tool，其余走 on_tool_call（T-6 多扩展派发聚合）

**验证**: 异语言 stdio 扩展（独立进程，不经 import core）握手互报 v0.1.0、before 钩子 action 还原、invoke_tool 执行/未实现、after 钩子内经宿主通道 storage_*/invoke_llm/task_* 全链路

### 任务 3.3: 进程监管 + 热重载 ✅

## 五、遗留项与说明

1. **process 握手协商收敛**（major 拒绝/minor 降级/双版本共存）归阶段 4 evolution 域——阶段 3 仅互报 `protocol_version` 字段（`peer_protocol_version` 记录，未强制）。
2. **进程僵死自动重建**：心跳超时当前仅 error 日志（阶段 3 记录），自动重建时序归阶段 4 生命周期域。
3. **route.py /chat 非流式响应对 intercepted 返回空 response**：既有行为（只收集 text_delta，不拼接 done.response），终止原因正确表达拦截，不属于阶段 3 范围，未改动。
4. Windows 下 asyncio 子进程退出时可能存在 `__del__` ResourceWarning 噪音（良性，不影响功能；`StdioChannel.close` 已显式清理 subprocess transport）。
5. 同语言扩展经 `host_port`（进程内消息通道）走 storage_*/invoke_llm 的冷路径已就绪，当前无同语言扩展实际消费（guardrails 无存储需求）；阶段 4 可加行为套件同语言用例对拍。
