## 二、任务逐项实现与验证

### 任务 4.1: evolution 版本协商 ✅

**文件**: 修改 `teage_liu2/core/transport.py`、`teage_liu2/core/stdio.py`

- `parse_protocol_version(version) -> (major, minor, patch)`（semver 正则，非法抛 ValueError）
- `negotiate_protocol_version(core, ext) -> {core_version, extension_version, compatible, action}`（对齐 evolution.schema.json ProtocolVersionNegotiation）:
  - major 不匹配（任一方向破坏性变更）→ `compatible=False, action="reject"`（握手失败，可读错误）
  - major 匹配且 ext.minor ≤ core.minor → `proceed`
  - major 匹配且 ext.minor > core.minor → `downgrade`（扩展按 core 能力子集降级，双版本共存过渡期 §10.2）
  - 扩展未上报版本 → 保守降级
- stdio 握手（`StdioChannel._handshake`）接入协商:major 拒绝抛 `StdioError`（启动失败）+ downgrade 记录日志；协商结果存 `channel.negotiation`

**验证**: 语义对拍 11/11（parse/proceed/downgrade/reject/缺失/非法）；握手集成 4/4（v1.0.0 启动、v1.2.0 降级、v2.0.0 拒绝启动）

### 任务 4.4: 会话并发互斥 + A8 无泄漏审计 ✅

**文件**: 新建 `teage_liu2/server/session_locks.py`；修改 `teage_liu2/server/app.py`、`teage_liu2/server/routes.py`

- **SessionLocks**:session 级 `asyncio.Lock` LRU 有界缓存（默认 10000）;LRU 淘汰只在锁**未被持有/等待**时进行（`lock.locked()` False），正在使用中的锁不可淘汰 —— 否则同 session 拿到两个不同锁破坏互斥
- `app.state.session_locks` 挂载;/chat 与 /chat/stream 在进入 pipeline.chat_stream 前获取 session 锁，覆盖整个对话流（SSE 流含 done/error 后释放）—— B3 根治
- **A8 审计**:配置注入真实格式 API Key 样本（`sk-test-...`）+ 内部路径样本,扫描对外输出通道（/chat 响应、SSE 事件、错误响应、/reload 响应、根端点、全部日志）→ 无泄漏

**验证**: SessionLocks 6/6（同 session 同一锁/串行化不交错/不同 session 不互斥/LRU 有界/drop）；A8 6/6

**修复的既有缺陷**(收口过程中发现):
- `StdioChannel.close` 自我取消:close 内 `task.cancel()` 取消 heartbeat_task(其正在 await on_dead→_auto_rebuild→close),导致重建被 CancelledError 中断 → 修复为跳过当前任务(`asyncio.current_task()`)。
- `StdioChannel.close` shutdown 等待 5s → 僵死进程不响应 shutdown,重建被拖慢 → shutdown_timeout 参数化(默认 1s,重建场景 0.3s)。

**行为套件全绿 = 16 用例 schema + runner 17/17 通过率 100%**。稳定面 v1.0 冻结无遗留项。
