## 一、设计目标

### 1.1 核心目标

| # | 目标 | 量化指标 |
|---|---|---|
| G1 | 消除单实例 director 死亡时的误判 | 单实例 director 死亡、远程有健康 director 时 **不触发 Election** |
| G2 | N 增大时心跳查询总延迟可控 | N=10 时跨实例心跳查询总延迟 **< 3s**（并发，不累积） |
| G3 | 选举触发条件正确 | 仅当**所有端点** director 都超时时才触发 Election |
| G4 | 与现有 Election 协作 | 不破坏选举仲裁（epoch + 字典序）；Election 胜出后启动 EmbeddedDirector |
| G5 | 不引入外部依赖 | 基于 A2A JSON-RPC，不引入 Redis/etcd |
| G6 | 同机/多机通用 | A2A over localhost 与 A2A over LAN 同一逻辑 |

### 1.2 非目标（明确排除）

- ❌ 不重写 Election 仲裁算法（仅调整其触发前置条件）
- ❌ 不解决共享 blackboard 全局一致性问题（方案 Y 各实例独立 blackboard 的最终一致性由 3.R1 处理）
- ❌ 不解决 agent_card 跨实例聚合视图（由 3.R1 处理）
- ❌ 不解决 director.md 跨实例同步写入（本设计仅**只读查询**远程 director.md）

### 1.3 与阶段 0/1/2 的衔接

```
阶段 1 任务1.1 已完成：_check_director_health 检测到本地超时 → 调 Election.run()
                              │
                              ▼
                  本设计 3.R2 要解决的差距：
                  Election 触发条件仍是"本地 director.md 超时"，
                  缺少"先查远程端点"的前置步骤
                              │
                              ▼
阶段 3.R2 本设计产出：
   _check_director_health 本地超时分支 → 先 _query_remote_director_health()
   → 任一远程健康 → 不进自治、不 Election，改为跟随远程 director
   → 所有远程超时 → 才触发 Election
```

## 二、现状分析

### 2.1 当前实现（阶段 1+2 后的真实状态）

#### 2.1.1 `_check_director_health` 当前逻辑（worker_adapter.py L1506-1582）

```python
async def _check_director_health(self) -> str:
    director_md = await read_director_md(self._bb_root)   # 仅读本地 director.md

        return "offline"
    last_tick = director_md.get("last_director_tick", "")
    if not last_tick:
        return "offline"
    tick_time = _parse_iso(last_tick)
    age = datetime.now(timezone.utc) - tick_time
    timeout = self._director_config.get("heartbeat_timeout_seconds", 30)
    ...

                election = Election(self._bb_root, self._agent_id, self._config)
                result = await election.run()
                if result.won:
```

**问题**：本地 `director.md` 超时即触发 Election，未先确认远程端点是否有健康 director。

#### 2.1.3 关键缺口与不一致（代码审查发现）

| # | 缺口 | 证据 | 影响 |
|---|---|---|---|
| GAP-1 | `Election._query_remote_directors` 调用 `call_all_endpoints("read_director_md", {})`（election.py L158），但 **`a2a_server.py` 未注册 `read_director_md` handler**（仅注册 send_message / query_capabilities / ping，见 a2a_server.py L63-67） | 远程查询必然返回 `-32601 Method not found` | Election 的远程候选收集**实际失效**，退化为仅本地候选 |
| GAP-2 | Election 期望远程返回 `status.director` 格式（含 agent_id/epoch/last_tick），但方法名 `read_director_md` 暗示返回 director.md frontmatter（含 director_id/current_epoch/last_director_tick） | 字段名不匹配（`last_tick` vs `last_director_tick`、`agent_id` vs `director_id`） | 即使 handler 注册了，Election 也解析不出候选 |
| GAP-3 | `_check_director_health` 本地超时分支**直接调 Election.run()**，无"先查远程心跳"前置 | worker_adapter.py L1532-1559 | 单实例 director 死亡即触发 Election（误判） |
| GAP-4 | `_check_director_health` 递归重检（L1559）无递归深度上限 | 选举失败 + 远程持续超时时可能无限递归 | 栈风险 / CPU 空转 |
| GAP-5 | `a2a_client` 无 `read_director_md` 专用方法（仅 `call_method`/`call_all_endpoints`） | a2a_client.py 全文 | 调用方需手写 method 名，易出错 |

### 2.2 N 增大时的恶化曲线

| N | 单实例 director 死亡概率（单次故障） | 当前实现触发 Election 概率 | 本设计后触发 Election 概率 |
|---|---|---|---|
| 2 | 50%（任一死亡） | 100%（本地死亡即触发） | 仅当两实例同时死亡（≈P²） |
| 5 | 20% | 100% | ≈P⁵（极低） |
| 10 | 10% | 100% | ≈P¹⁰（可忽略） |

**核心收益**：本设计将"单点死亡触发选举"降级为"全端点死亡触发选举"，N 越大收益越大。

### 2.3 待解决差距汇总

- 缺少 `read_director_md` A2A JSON-RPC handler 实现（GAP-1）
- 缺少 Election 远程返回格式与 director.md 字段的调和（GAP-2）
- `_check_director_health` 缺少远程端点查询前置步骤（GAP-3）
- 递归重检无深度上限（GAP-4）
- `a2a_client` 缺少语义化 `read_director_md` 方法（GAP-5）

## 三、设计方案

### 3.1 跨实例心跳查询 API 设计

#### 3.1.1 协议选型：JSON-RPC（非 REST GET）

任务描述提到 `GET /api/multiagent/a2a/director_md`，但现有 A2A 通信**全部走 JSON-RPC 2.0 over POST `/a2a/jsonrpc`**（a2a_server.py L84、a2a_client.py L71）。为保持一致性：

- **主通道**：JSON-RPC 方法 `read_director_md`（注册到 `A2AServer._handlers`）
- **辅助通道（可选）**：REST `GET /api/multiagent/a2a/director_md` 供人工调试/curl 调用，复用同一 handler

**推荐**：仅实现 JSON-RPC 方法（主通道），REST 端点作为 P2 可选增强。

#### 3.1.2 返回格式：统一 director.md frontmatter + 派生字段

为同时满足 GAP-1（handler 缺失）与 GAP-2（Election 字段不一致），返回**统一载体**：

```json
{
  "director_id": "teagent-lu",
  "director_implementation": "agent",
  "current_epoch": 3,
  "epoch_started_at": "2026-07-30T10:00:00+00:00",
  "last_director_tick": "2026-07-30T10:05:12+00:00",
  "heartbeat": {
    "interval_seconds": 10,
    "timeout_seconds": 30
  },
  "turn_policy": { "mode": "round_robin", "order": [] },
  "source_endpoint": "teagent-lu",
  "queried_at": "2026-07-30T10:05:15+00:00",
  "is_stale": false,
  "age_seconds": 3.1
}
```

**调和策略**：
- 前 7 个字段直接来自本地 `director.md` frontmatter（`read_director_md(bb_root)` 返回值）
- `source_endpoint` / `queried_at` / `is_stale` / `age_seconds` 由 handler 派生计算
- **Election 改造**：`_query_remote_directors` 不再期待 `status.director` 子结构，改为直接消费本格式（字段映射：`director_id`→候选 agent_id、`current_epoch`→epoch、`last_director_tick`→last_tick）。此为 GAP-2 的修复点。

#### 3.1.3 端点路由拓扑

```
┌─────────────────────────────────────────────────────────────────┐
│  实例 A (teagent-lu, port 8000)                                  │
│  ┌────────────────────────────────────────────┐                  │
│  │ A2AServer._handlers                        │                  │
│  │  ├─ send_message (内置)                    │                  │
│  │  ├─ query_capabilities (内置)              │                  │
│  │  ├─ ping (内置)                            │                  │
│  │  └─ read_director_md (本设计新增) ◀────────┼──── JSON-RPC    │
│  └────────────────────────────────────────────┘                  │
│  director.md (本地心跳源)                                        │
└──────────┬──────────────────────────────────────────────────────┘
           │ POST /a2a/jsonrpc
           │ {method:"read_director_md", params:{}}
           ▼
┌─────────────────────────────────────────────────────────────────┐
│  实例 B (teagent-liu-2, port 8001)                               │
│  A2AClient.call_all_endpoints("read_director_md", {})            │
│   ├─ 并发 gather 所有 remote_endpoints                           │
```

### 3.2 查询算法（核心决策逻辑）

#### 3.2.1 三阶段判定流程

```
_check_director_health()
        │
        ▼
┌───────────────────────┐
│ 阶段 1：本地判定       │
│ 读本地 director.md    │
│ 计算 age              │
└──────────┬────────────┘
           │
     ┌─────┴─────┐
     │ age < to? │──Yes──▶ 返回 "healthy" / "degraded"
     └─────┬─────┘
           │ No (本地超时)
           ▼
┌───────────────────────┐
│ 阶段 2：远程查询       │  ◀── 本设计核心新增
│ _query_remote_director │
│ _health()              │
│ 并发查所有 N-1 端点    │
│ 总超时 3s              │
└──────────┬────────────┘
           │
     ┌─────┴──────────┐
     │ 任一远程健康?   │
     └─────┬──────────┘
       Yes │            No（全部超时/不可达）
           ▼            ▼
┌──────────────────┐  ┌───────────────────┐
│ 阶段 3a：跟随远程 │  │ 阶段 3b：触发选举 │
│ 不进自治          │  │ Election.run()    │
│ 不 Election       │  │ 胜→启动本地 dir  │
│ 返回 "healthy_    │  │ 败→等待+重检(有限)│
│   remote"         │  │ 全败→进自治       │
└──────────────────┘  └───────────────────┘
```

#### 3.2.2 "远程健康"判定标准

远程端点返回的 director_md 满足以下**全部**条件视为健康：
1. 返回非异常（非 `A2AClientError`）
2. `last_director_tick` 非空且可解析
3. `age_seconds < timeout_seconds`（用远程 director.md 自身的 `heartbeat.timeout_seconds`，而非本地配置）
4. `current_epoch >= 本地 current_epoch`（防止跟随陈旧 epoch 的僵尸 director）

> **设计要点**：用远程 director.md 自身的 `timeout_seconds` 判定，而非本地配置。原因是各实例 timeout 配置可能不同（如滚动升级期），用源数据自身的阈值更准确。

#### 3.2.3 "跟随远程"的含义

返回 `healthy_remote` 后，`_check_director_health` 不进自治、不 Election。本机继续：
- 周期性轮询本地 director.md（远程 director 通过方案 Y 的 A2A 同步机制把心跳写到本地——此为 3.R1 范围）
- 下次 `_check_director_health` 调用时重新走三阶段判定

> **注意**：本设计不负责"把远程 director.md 同步到本地"——那是方案 Y 的 A2A 同步子机制（3.R1）。本设计仅做**只读查询判定**。在 3.R1 落地前，`healthy_remote` 状态下本机仍可能因本地 director.md 持续陈旧而反复进入远程查询；这是可接受的过渡态（每次查询 < 3s，不会触发误选举）。

### 3.3 查询超时控制

#### 3.3.1 超时层级

| 层级 | 超时值 | 来源 | 说明 |
|---|---|---|---|
| L1 单端点 HTTP | 3s | `a2a_client._timeout`（任务2.2 已调） | 单次 JSON-RPC POST 超时 |
| L2 单端点含重试 | ≤5s | retry_count=1 + 指数退避 0.5s | 3s + 0.5s + 3s ≈ 6.5s（最坏） |
| L3 全端点并发总时长 | 3s（目标） | `asyncio.gather` + `return_exceptions=True` | 并发而非串行 |

**关键**：L3 总时长由**最慢的成功端点**决定。由于 `return_exceptions=True`，失败端点立即返回异常对象不阻塞。最坏情况下所有端点都在重试，总时长 ≈ L2（6.5s）。

#### 3.3.2 强制总超时保护

为避免 L2 最坏情况拖累 L3，在 `_query_remote_director_health` 外层包一个 `asyncio.wait_for(..., timeout=query_total_timeout)`：

```python
# 推荐配置：query_total_timeout = 5s（略大于 L2，给重试留空间，但封死上界）
QUERY_TOTAL_TIMEOUT = self._director_config.get("remote_query_total_timeout_seconds", 5)
try:
    results = await asyncio.wait_for(
        self._a2a_client.call_all_endpoints("read_director_md", {}),
        timeout=QUERY_TOTAL_TIMEOUT,
    )
except asyncio.TimeoutError:
    logger.warning("远程 director 查询总超时 %ss，视为全部不可达", QUERY_TOTAL_TIMEOUT)
    results = {}  # 视为全部失败
```

#### 3.3.3 N 增大时的延迟特性

```
N=2:  1 个远程端点，并发=1，总时长 ≈ L2 = 6.5s（最坏） / 3s（典型）
N=5:  4 个远程端点，并发=4，总时长 ≈ L2 = 6.5s（最坏，并发不累积）
N=10: 9 个远程端点，并发=9，总时长 ≈ L2 = 6.5s（最坏，并发不累积）
```

**结论**：总延迟不随 N 线性增长（并发特性），但 N 增大时 A2A 调用风暴风险上升（见 3.5 / 六）。

### 3.4 选举与心跳查询的协作

#### 3.4.1 触发顺序契约

```
心跳查询优先（先查 → 再决定是否 Election）
        │
        ▼
   远程有健康 director? ──Yes──▶ 不 Election（跟随远程）
        │ No
        ▼
   触发 Election.run()
        │
   ┌────┴────┐
   │ won?    │
   └────┬────┘
     Yes│         No
        ▼         ▼
   启动 Embedded  等待 election_wait_seconds
   Director       有限次重检（≤2 次，避免无限递归）
   返回 "healthy"     │
                       ▼
                  重检仍超时 → 进入自治（fallback）
```

#### 3.4.2 Election 触发前置条件调整

Election 本身不改仲裁算法，仅在 `_check_director_health` 调用侧加前置：

| 调用点 | 改造前（阶段1） | 改造后（本设计） |
|---|---|---|
| `_check_director_health` 本地超时分支 | 直接 `Election.run()` | 先 `_query_remote_director_health()`；远程全超时才 `Election.run()` |

#### 3.4.3 防无限递归（修 GAP-4）

阶段 1 实现中 `_check_director_health` 选举失败后递归调用自身（worker_adapter.py L1559），远程持续超时时会无限递归。本设计引入 `_recheck_count` 限制：

```python
async def _check_director_health(self, _recheck_depth: int = 0) -> str:
    ...
    if 选举失败:
        if _recheck_depth < MAX_RECHECK_DEPTH:  # 默认 2
            await asyncio.sleep(election_wait_seconds)
            return await self._check_director_health(_recheck_depth + 1)
        else:
            logger.warning("重检深度达上限 %s，进入自治", MAX_RECHECK_DEPTH)
            # 进入自治 fallback
```

### 3.5 N 增大时的扩展性考量

#### 3.5.1 并发查询策略

- **并发查询所有 N-1 个端点**：`asyncio.gather` + `return_exceptions=True`（复用 `a2a_client.call_all_endpoints` 现有能力）
- **失败端点不阻塞**：异常作为返回值，不中断其他端点查询
- **总延迟不随 N 增长**：并发而非串行

#### 3.5.2 A2A 调用风暴缓解

N=10 时，每个 `_check_director_health` 周期（默认 5s）会触发 9 次 A2A 调用。若所有实例同时检测到本地超时，瞬时调用数 = 10×9 = 90 次。缓解措施：

| 措施 | 实现 | 优先级 |
|---|---|---|
| 查询限流：每实例同时只允许 1 个 `_query_remote_director_health` 在飞 | `asyncio.Lock` 包住查询 | P0 |
| 查询退避：本地 director 刚超时后，首次查询立即；连续超时则查询间隔退避到 15s | `_remote_query_backoff` 状态机 | P1 |
| 端点级熔断：连续 3 次失败的端点，下次查询跳过（30s 冷却） | `_endpoint_circuit_breaker` dict | P2 |

> **推荐**：P0 必做（防风暴），P1/P2 视长跑测试结果决定。

#### 3.5.3 端点列表来源（待决策项 D-2）

| 选项 | 来源 | 优点 | 缺点 |
|---|---|---|---|
| 静态 | `config["a2a"]["remote_endpoints"]` | 简单、可预测 | 增减实例需改配置重启 |
| 动态 | A2A discovery（端点间互查 agent_card） | 弹性扩缩容 | 需新增 discovery 协议，复杂度高 |

**推荐**：**静态**（与现有 `a2a_client` 一致，N≤10 中规模够用）。动态留待大规模 N>10 时再考虑。

## 四、接入点

### 4.1 `worker_adapter._check_director_health` 改造

**文件**：`teage_liu/multiagent/worker_adapter.py`（L1506-1582）

**改造点**：
1. 本地超时分支 → 调 `_query_remote_director_health()`（新增方法）
2. 远程查询返回任一健康 → 返回 `"healthy_remote"`（新增健康级别）
3. 远程查询全部超时 → 触发 Election（原逻辑）
4. 新增 `_recheck_depth` 参数防无限递归（修 GAP-4）
5. 新增 `_remote_query_lock` 防查询风暴（3.5.2 P0）

**新增健康级别**：`"healthy"` / `"healthy_remote"` / `"degraded"` / `"offline"`

> **注意**：`healthy_remote` 是新级别，调用方（`_director_monitor_loop`、`_check_director_recovery`）需识别。`_check_director_recovery` 当前仅对 `healthy` 触发自治退出，`healthy_remote` 应等同 `healthy` 处理（远程 director 活着 = 自治可退出）。

### 5.1 `a2a_server.py` 新增 `read_director_md` handler

```python
# a2a_server.py —— 在 _register_builtin_handlers 中追加
def _register_builtin_handlers(self) -> None:
    """注册内置 JSON-RPC 方法。"""
    self._handlers["send_message"] = self._handle_send_message
    self._handlers["query_capabilities"] = self._handle_query_capabilities
    self._handlers["ping"] = self._handle_ping
    self._handlers["read_director_md"] = self._handle_read_director_md  # 新增

async def _handle_read_director_md(self, params: dict) -> dict:
    """内置 read_director_md 方法：返回本地 director.md frontmatter + 派生健康字段。

    供跨实例 Director 心跳查询使用（3.R2）。返回 3.1.2 定义的统一载体格式。
    无需签名校验（director.md 是协议公开状态，非敏感数据）。
    """
    from datetime import datetime, timezone
    from teage_liu.multiagent.blackboard import read_director_md

    director_md = await read_director_md(self._bb_root)
    if not director_md:
        # 本地无 director.md（未初始化或首次启动）
        return {
            "director_id": "",
            "current_epoch": 0,
            "last_director_tick": "",
            "heartbeat": {"interval_seconds": 10, "timeout_seconds": 30},
            "source_endpoint": self._agent_id,
            "queried_at": datetime.now(timezone.utc).isoformat(),
            "is_stale": True,        # 无 tick 视为 stale
            "age_seconds": None,
        }

    # 派生健康字段
    last_tick = director_md.get("last_director_tick", "")
    timeout = director_md.get("heartbeat", {}).get("timeout_seconds", 30)
    is_stale = True
    age_seconds = None
    if last_tick:
        try:
            tick_dt = datetime.fromisoformat(last_tick.replace("Z", "+00:00"))
            age = datetime.now(timezone.utc) - tick_dt
            age_seconds = age.total_seconds()
            is_stale = age.total_seconds() > timeout
        except (ValueError, TypeError):
            is_stale = True

    return {
        **director_md,                       # 原始 frontmatter 字段透传
        "source_endpoint": self._agent_id,   # 标识来源实例
        "queried_at": datetime.now(timezone.utc).isoformat(),
        "is_stale": is_stale,
        "age_seconds": age_seconds,
    }
```

### 5.3 `worker_adapter.py` 新增 `_query_remote_director_health`

```python
# worker_adapter.py —— WorkerAdapter 类内新增

def __init__(self, ...):
    ...
    # 3.R2 新增：远程查询基础设施
    self._a2a_client = None  # 延迟初始化（仅 director_v2_enabled 时创建）
    self._remote_query_lock = asyncio.Lock()  # 防查询风暴（3.5.2 P0）
    self._remote_query_last_ts: float = 0.0   # 上次查询时间戳（退避用）

def _ensure_a2a_client(self):
    """延迟初始化 A2AClient（仅当配置了 a2a 段时）。"""
    if self._a2a_client is None:
        a2a_cfg = self._config.get("a2a") or self._director_config.get("a2a")
        if a2a_cfg:
            from teage_liu.multiagent.a2a_client import A2AClient
            self._a2a_client = A2AClient({"a2a": a2a_cfg})
    return self._a2a_client

async def _query_remote_director_health(self) -> tuple[str, dict | None]:
    """查询所有远程端点的 director 心跳健康状态（3.R2 核心）。

    Returns:
        (status, healthy_remote_md)
        - status: "healthy_remote" / "all_stale"
        - healthy_remote_md: status=healthy_remote 时为首个健康端点的 director_md dict；
          status=all_stale 时为 None
    """
    client = self._ensure_a2a_client()
    if client is None:
        # 未配置 a2a（单实例部署），无远程可查，直接判全超时
        logger.debug("Worker %s 未配置 A2A，跳过远程 director 查询", self._agent_id)
        return "all_stale", None

    total_timeout = self._director_config.get("remote_query_total_timeout_seconds", 5)

    # 防查询风暴：同一时刻仅一个查询在飞
    async with self._remote_query_lock:
        try:
            results = await asyncio.wait_for(
                client.call_all_endpoints("read_director_md", {}),
                timeout=total_timeout,
            )
        except asyncio.TimeoutError:
            logger.warning(
                "Worker %s 远程 director 查询总超时 %ss",
                self._agent_id, total_timeout,
            )
            return "all_stale", None
        except Exception as e:
            logger.warning("Worker %s 远程 director 查询异常: %s", self._agent_id, e)
            return "all_stale", None

    # 遍历结果，找首个健康端点
    local_epoch = await self._read_local_epoch()
    for ep_name, result in results.items():
        if isinstance(result, Exception):
            # 该端点查询失败（网络/超时/JSON-RPC error），跳过
            logger.debug(
                "Worker %s 端点 %s 查询失败: %s", self._agent_id, ep_name, result,
            )
            continue
        if not isinstance(result, dict):
            continue

        # 健康判定（3.2.2 四条件）
        if result.get("is_stale") is False:
            remote_epoch = result.get("current_epoch", 0)
            if remote_epoch >= local_epoch:
                logger.info(
                    "Worker %s 远程端点 %s director 健康（epoch=%s, age=%.1fs）",
                    self._agent_id, ep_name, remote_epoch,
                    result.get("age_seconds") or 0.0,
                )
                return "healthy_remote", result
            else:
                logger.debug(
                    "Worker %s 端点 %s epoch=%s < 本地=%s，视为陈旧",
                    self._agent_id, ep_name, remote_epoch, local_epoch,
                )

    return "all_stale", None

async def _read_local_epoch(self) -> int:
    """读取本地 director.md 的 current_epoch。"""
    director_md = await read_director_md(self._bb_root)
    return director_md.get("current_epoch", 0) if director_md else 0
```

### 5.4 `_check_director_health` 改造后完整逻辑

```python
# worker_adapter.py —— 改造 _check_director_health（L1506-1582）

# 模块级常量
MAX_RECHECK_DEPTH = 2  # 选举失败后重检深度上限（防无限递归，修 GAP-4）

async def _check_director_health(self, _recheck_depth: int = 0) -> str:
    """检查 Director 心跳健康状态（3.R2 改造版）。

    Returns:
        健康级别："healthy" / "healthy_remote" / "degraded" / "offline"

    副作用：
    - "offline" 且未自治时：先查远程 → 远程全超时才 Election / 自治
    - "healthy" / "healthy_remote" 且自治中时：触发 _check_director_recovery
    """
    director_md = await read_director_md(self._bb_root)
    if not director_md:
        return await self._handle_local_offline(director_md or {}, _recheck_depth)

    last_tick = director_md.get("last_director_tick", "")
    if not last_tick:
        return await self._handle_local_offline(director_md, _recheck_depth)

    tick_time = _parse_iso(last_tick)
    age = datetime.now(timezone.utc) - tick_time
    timeout = self._director_config.get("heartbeat_timeout_seconds", 30)
    interval = director_md.get("heartbeat", {}).get("interval_seconds", 10)
    degraded_threshold = self._director_config.get(
        "degraded_threshold_seconds", interval * 2
    )

    if age > timedelta(seconds=timeout):
        # 本地超时 → 走远程查询 + Election 流程
        return await self._handle_local_offline(director_md, _recheck_depth)
    elif age >= timedelta(seconds=degraded_threshold):
        return "degraded"
    else:
        # 本地健康
        if self._autonomous_mode or self._autonomous.is_active:
            if self._autonomous_mode and not self._autonomous.enabled:
                await self._check_director_recovery()
        return "healthy"

async def _handle_local_offline(
    self, local_director_md: dict, _recheck_depth: int
) -> str:
    """本地 director 超时后的处理：远程查询 → Election → 自治。"""
    if self._autonomous_mode or self._autonomous.is_active:
        # 已在自治，无需重复触发
        return "offline"

    if not self._config.get("director_v2_enabled", True):
        # 旧路径：直接进自治
        epoch = local_director_md.get("current_epoch", 0)
        await self._autonomous.enter(reason="director_heartbeat_timeout", epoch=epoch)
        self._autonomous_mode = True
        self._autonomous_epoch = epoch
        return "offline"

    # ===== 3.R2 核心：先查远程 =====
    if self._director_config.get("remote_query_enabled", True):
        status, healthy_md = await self._query_remote_director_health()
        if status == "healthy_remote":
            # 远程有健康 director → 不 Election、不自治，跟随远程
            logger.info(
                "Worker %s 本地 director 超时，但远程端点 %s 健康，跟随远程",
                self._agent_id, healthy_md.get("source_endpoint"),
            )
            return "healthy_remote"

    # ===== 远程全超时 → 触发 Election =====
    try:
        from teage_liu.multiagent.election import Election
        election = Election(self._bb_root, self._agent_id, self._config)
        result = await election.run()
        if result.won:
            logger.info("本机选举胜出 epoch=%s，启动 Director", result.epoch)
            if self._director_manager:
                await self._director_manager.start()
                return "healthy"  # 自己接管后视为健康
            # 无 director_manager：落到自治
        else:
            logger.info("选举失败，胜者=%s，等待其心跳", result.director_id)
            if _recheck_depth < MAX_RECHECK_DEPTH:
                await asyncio.sleep(
                    self._director_config.get("election_wait_seconds", 5)
                )
                return await self._check_director_health(_recheck_depth + 1)
            else:
                logger.warning(
                    "重检深度达上限 %s，进入自治", MAX_RECHECK_DEPTH,
                )
    except Exception as e:
        logger.exception("选举异常，回退到自治模式: %s", e)

    # Election 失败 / 异常 / 重检耗尽 → 进入自治
    epoch = local_director_md.get("current_epoch", 0)
    await self._autonomous.enter(reason="director_heartbeat_timeout", epoch=epoch)
    self._autonomous_mode = True
    self._autonomous_epoch = epoch
    return "offline"
```

### 5.5 `election.py` 远程返回格式调和（修 GAP-2）

```python
# election.py —— 改造 _query_remote_directors 与候选收集（L74-78）

async def run(self) -> ElectionResult:
    local_status = await self._read_local_status()
    local_director = (local_status or {}).get("director", {}) if local_status else {}
    remote_directors = await self._query_remote_directors()

    candidates: list[dict] = []
    if local_director:
        candidates.append(local_director)

    # 改造：消费 3.1.2 统一载体格式（而非 status.director 子结构）
    for ep_name, remote_md in remote_directors.items():
        if isinstance(remote_md, dict) and remote_md.get("director_id"):
            # 字段映射：director.md 格式 → 候选格式
            candidates.append({
                "agent_id": remote_md.get("director_id", ""),
                "epoch": remote_md.get("current_epoch", 0),
                "last_tick": remote_md.get("last_director_tick", ""),
                "source": ep_name,
                "is_stale": remote_md.get("is_stale", True),
            })

    if not candidates:
        return await self._win_election(0, "no_candidates")

    max_epoch = max(c.get("epoch", 0) for c in candidates)
    highest_epoch_candidates = [
        c for c in candidates if c.get("epoch", 0) == max_epoch
    ]

    current_director = next(
        (c for c in highest_epoch_candidates if c.get("agent_id")), None,
    )
    if current_director:
        # 改造：优先用远程返回的 is_stale，回退到本地计算
        is_stale = current_director.get("is_stale")
        if is_stale is None:
            is_stale = self._is_director_stale(current_director)
        if is_stale and len(highest_epoch_candidates) == 1:
            return await self._win_election(max_epoch + 1, "preempt_stale")

        winner_id = min(c.get("agent_id", "") for c in highest_epoch_candidates)
        if winner_id == self._agent_id:
            return await self._win_election(max_epoch, "tie_break_win")
        return ElectionResult(
            won=False, director_id=winner_id, epoch=max_epoch,
            reason="tie_break_loss" if len(highest_epoch_candidates) > 1 else "lower_epoch",
        )

    return await self._win_election(max_epoch, "no_active_director")
```

## 六、风险与缓解

| # | 风险 | 概率 | 影响 | 缓解措施 |
|---|---|---|---|---|
| R1 | 远程查询超时累积（L2 最坏 6.5s）拖慢 `_check_director_health` | 中 | 监测循环卡顿 | L3 `asyncio.wait_for` 总超时 5s 封顶；`_remote_query_lock` 防并发 |
| R2 | 网络分区导致本机误判"远程全超时"→ 触发不必要 Election → 双 director | 中 | 脑裂风险 | Election 仲裁仍用 epoch + 字典序；`director.lock` 互斥锁兜底防双 director 同机；分区恢复后高 epoch 胜出 |
| R3 | 选举与心跳查询竞态：查询返回 healthy_remote 同时另一实例刚 Election 胜出 | 低 | 短暂视图不一致 | 容忍最终一致；下次 5s 周期重检自动校正；`healthy_remote` 不写状态，仅影响本次决策 |
| R4 | N 增大时 A2A 调用风暴（N=10 → 90 调用/5s） | 中 | 网络拥塞 / 端点过载 | `_remote_query_lock` 限每实例 1 在飞查询；P1 退避；P2 端点熔断 |
| R5 | 远程 director.md 字段缺失（旧版本兼容）→ 健康判定误判 | 低 | 误跟随陈旧 director | 健康判定四条件全 AND；任一缺失视为 stale；`is_stale` 字段缺失回退到本地计算（5.5） |
| R6 | `healthy_remote` 级别未被 `_check_director_recovery` 识别 | 中 | 自治无法退出 | 改造 `_check_director_recovery`：`healthy_remote` 等同 `healthy` 触发退出流程（4.1 注意点） |
| R7 | 递归重检 `_recheck_depth` 未传递导致绕过上限 | 低 | 栈风险 | 5.4 骨架中 `_recheck_depth` 作为参数显式传递，递归调用时 +1 |
| R8 | 远程端点返回伪造 director.md（无签名校验） | 低 | 误跟随恶意 director | `read_director_md` 是协议公开状态，篡改影响有限；后续可加 ed25519 签名（与 send_message 一致） |

## 九、待用户决策

### D-1：心跳查询频率

| 选项 | 描述 | 优点 | 缺点 |
|---|---|---|---|
| **A. 按需查询（推荐）** | 每次本地 director.md 超时时触发远程查询 | 流量小、逻辑简单；正常态零流量 | 故障检测延迟 = 本地 timeout（30s） |
| B. 定期后台查询 | 独立协程每 N 秒查所有端点，缓存结果 | 检测延迟低（可达 timeout/2） | 持续 A2A 流量；缓存一致性问题 |
| C. 混合 | 平时按需，检测到本地 degraded 时升级为定期 | 平衡 | 复杂度高 |

**推荐 A**：与现有 `_director_monitor_loop` 5s 周期 + 本地 30s timeout 自然契合，正常态零远程流量。N≤10 中规模下 30s 检测延迟可接受（director 心跳超时本就是 30s 阈值）。

### D-2：远程端点列表来源

| 选项 | 描述 | 优点 | 缺点 |
|---|---|---|---|
| **A. 静态 config（推荐）** | `config.a2a.remote_endpoints` | 简单、可预测、与现有 a2a_client 一致 | 增减实例需改配置重启 |
| B. 动态 A2A discovery | 端点间互查 agent_card 发现彼此 | 弹性扩缩容 | 需新增 discovery 协议，复杂度高 |

**推荐 A**：N≤10 中规模、渐进优先、暂不引入外部依赖的决策框架下，静态足够。动态留待 N>10 大规模时再考虑。

### D-3：查询失败重试策略

| 选项 | 描述 | 优点 | 缺点 |
|---|---|---|---|
| A. 单次无重试 | 远程查询失败即视为该端点 stale | 快速失败（3s 上限） | 偶发网络抖动误判 |
| **B. 复用 a2a_client 重试（推荐）** | 沿用 retry_count=1（共 2 次）+ 指数退避 | 与现有 A2A 调用一致 | 单端点最坏 6.5s |
| C. 指数退避（独立） | 远程查询用更长退避（1s/2s/4s） | 抗抖动 | 拖慢总查询 |

**推荐 B**：复用任务 2.2 已调好的 `a2a_client`（timeout=3s, retry=1, 退避 0.5→2.0s），不引入新的重试策略。L3 总超时 5s 兜底。

### D-4：`healthy_remote` 状态下是否同步远程 director.md 到本地

| 选项 | 描述 | 优点 | 缺点 |
|---|---|---|---|
| A. 不同步（仅判定用） | 本设计范围；本地 director.md 仍陈旧 | 职责单一，与 3.R1 解耦 | 本地协作视图可能短暂不一致 |
| **B. 不同步（推荐）** | 同 A | 同 A | 同 A |

**推荐 B（=A）**：本设计是**只读查询判定**，不写本地 director.md。同步远程 director.md 到本地是方案 Y 的 A2A 同步子机制，属于 3.R1（嵌入式 Director 设计）范围。在 3.R1 落地前，`healthy_remote` 状态下本机继续按本地陈旧 director.md 运行协作轮询，但**不会误触发 Election**——这正是本设计的核心价值。
