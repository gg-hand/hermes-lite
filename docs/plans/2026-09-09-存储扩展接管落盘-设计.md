# 存储扩展接管 liu2 落盘存储 — 设计

> 日期：2026-09-09。状态：设计定案（用户逐项确认），执行计划见
> `docs/plans/2026-09-09-存储扩展接管落盘-执行计划.md`。

## 1. 目标

存储后端以**扩展形态**接管 liu2 的全部落盘（通用落盘平台 + 会话消息历史），
liu2 源码污染最小化，core 契约零改动，扩展侧支持任意语言。

## 2. 决策记录（用户定案）

| 决策点 | 结论 |
|---|---|
| 接管范围 | `StorageProvider` + `HistoryStore`/`MessageStore` 两条通道都接管 |
| 接管方式 | 静态：启动时配置 → 装配点注入，运行中不切换 |
| 扩展形态 | 异语言：存储引擎为独立子进程（任意语言），stdio 通信 |
| 存量数据 | 不迁移，新后端从零开始；`data/sessions.db` 留给老系统/备查 |
| 源码边界 | 桥接不进扩展包，也不做后端专属代码——外壳只放**通用机制**（装载器）+ **通用协议实现**（stdio 代理），均不随后端变化 |

## 3. 总体架构

```
pipeline ──HistoryStore/MessageStore──┐
                                      ├─→ StdioStorageProxy（外壳通用代理）
transport storage_* ──StorageProvider─┘        │ JSON Lines over stdio
                                               ▼
                                     存储后端子进程（任意语言）
```

- **core 零改动**：`core/storage.py`、`core/history.py`、`core/transport.py`、
  `core/storage_writer.py` 原样；铁律不违反（core 不知道任何枝干，新代码全在 `server/`）。
- **不配置即默认**：`host_components` 缺省 = 全部插槽走 core 默认 SQLite，一行不变。

## 4. 插槽制装载器（协议候选 P-5）

外壳新增 `teage_liu2/server/host_components.py`：

```python
SLOTS = {                       # 插槽白名单：插槽名 → 必须实现的 core ABC
    "storage": (StorageProvider,),
    "history": (HistoryStore, MessageStore),
}
BACKENDS = {                    # 插槽 → backend 名 → 工厂（factory(cfg, options) -> {slot: obj}）
    "storage": {"sqlite": _sqlite_backend, "stdio-proxy": _stdio_proxy_backend},
}
```

- config：

```yaml
host_components:            # 缺省省略 = 全部 core 默认
  - slot: storage           # 当前唯一插槽
    backend: stdio-proxy    # 或省略整段 = sqlite 默认
    options:                # backend 私有选项
      command: ["<任意语言后端启动命令>"]
      request_timeout_seconds: 10
```

- 装载流程：读 `host_components` → slot 白名单校验 → backend 注册表解析 →
  工厂返回 `{slot: obj}` → **isinstance 快速失败**（不满足插槽 ABC = 启动失败，
  符合"不静默降级"）→ 重复接管同一插槽 = 启动失败。
- 生命周期免费获得：注入对象走现有装配/关闭链（`registry.shutdown` 的
  `message_store.close` / `storage_provider.close`），代理 close 幂等。
- 未来扩展：新插槽 = `SLOTS` 加一行；新 backend 形态 = `BACKENDS` 注册一行，
  装载器本体永不再改。

## 5. stdio 通用代理与线协议（协议候选 P-4）

`teage_liu2/server/storage_stdio_proxy.py`：`StdioStorageProxy` 同时实现
`StorageProvider` + `HistoryStore` + `MessageStore`（表面 = HistoryStore + MessageStore
ABC 全部方法；`create_session` 等 SQLite 实现特有方法不纳入——无生产调用方）。

### 5.1 帧格式（JSON Lines over stdio）

```jsonc
// 请求（host → backend stdin）
{"id": 1, "op": "query", "p": {"kind": "audit", "limit": 10}}
// 响应（backend stdout → host）
{"id": 1, "ok": true,  "r": [{"...": "..."}]}
{"id": 1, "ok": false, "e": "可读错误信息"}
```

- op 集 = 代理公开方法一一映射：
  `write / read / query / delete`（StorageProvider）、
  `ensure_session / log_message / get_session_messages / update_session_title /
  get_session_title / search_messages`（HistoryStore/MessageStore）。
- 握手：首帧 `{"id":0,"op":"hello","p":{"protocol":"storage-stdio","version":"0.1.0"}}`，
  major 不匹配 = 启动失败；关闭：`{"op":"bye"}` + 超时终止兜底。
- stderr 由宿主透传到日志。

### 5.2 语义条款（后端实现方必须满足）

1. kind 白名单 `^[a-z0-9_.]+$`（宿主侧 `core.storage._validate_kind` 先行校验，双重防线）；
2. `query` 按**写入序**返回，`filters` 为 doc 顶层字段精确匹配；
3. 批量写 `docs[]` 原子提交；
4. **write 响应 `r` 恒为 doc_id 数组**（单条与批量一致，顺序对应 docs；宿主单条写取 `[0]`）；
5. `search_messages` 全文检索语义 = **子串匹配即可**（FTS5 是 SQLite 实现细节，非契约）；
6. 后端单进程内串行应答（一请求一响应，帧序即完成序）；
7. **帧编码必须 UTF-8**（stdout/stderr 均是；Python 后端在 Windows 默认 GBK，须显式 reconfigure，宿主对非 UTF-8 数据快速失败）。

### 5.3 代理并发模型

- 代理内嵌**独立 IO 线程 + 专用事件循环**（同 `StorageWriter` 的线程模型，
  不依赖主循环生命周期）：asyncio 子进程读写 + 请求 id 关联 future。
- 同步方法（`StorageWriter` 写线程、`asyncio.to_thread` 读路径直接兼容）：
  `run_coroutine_threadsafe` 投递到内部循环 + 超时等待。
- 错误处理遵循降级优先：请求超时/断连抛异常；写路径由 StorageWriter 现有
  兜底吞掉记日志（主对话不中断）；读路径异常向上冒泡由调用方降级。

## 7. 验收

1. 默认路径回归：不配置 `host_components`，启动/聊天/重启恢复与现状一致；
2. stdio 路径端到端：`backend: stdio-proxy` 启动（参考后端）→ 聊天若干轮 →
   重启 → 会话历史与 doc 数据由后端完整重建；
3. 快速失败：未知插槽/未知 backend/握手失败/ABC 不满足 → 启动失败且错误可读；
4. 参考后端为联调临时件，放仓库外临时目录，验收后删除（仓库纯净）。
