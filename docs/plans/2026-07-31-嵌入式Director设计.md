## 一、设计目标

| # | 目标 | 量化指标 | 对应解决的根本问题 |
|---|---|---|---|
| G1 | 消除子进程僵尸风险 | 嵌入式路径下 0 个 `director_cli` 子进程 | 旧模式依赖 `subprocess.Popen` + `director.lock` 持锁，崩溃后锁残留导致新实例无法启动（P5） |
| G2 | Director 可在任一 worker 实例上运行（迁移能力） | 原 Director 死亡 → 新实例接管 ≤ 30s | 阶段 1 任务 1.1 已接入 `Election.run()`，但胜出后仅 fallback 到自治；本设计让胜出者真正启动 `_run_loop` |
| G3 | 单点故障 30s 内自动 failover | 选举触发到 `_run_loop` 首次 tick ≤ 2s | 阶段 1.4 / 1.5 已缓解子进程僵尸，但未消除"Director 与某 worker 强绑定"的脆弱性 |
| G4 | 与现有 LocalDirectorManager 共存（可降级回退） | `director_v2_enabled=False` 一键回退到子进程模式 | 渐进式上线要求：新路径异常时不阻断服务 |
| G5 | worker 主循环不受 director 运行影响 | LLM 调用 99 分位延迟不退化（对比阶段 2 基线 ±10%） | 嵌入式让 director 与 worker 共享 event loop，需隔离避免互相拖累 |
| G6 | 跨实例状态最终一致（方案 Y） | status.json 跨实例同步延迟 ≤ 5s | 各实例独立 `blackboard_a2a_X`，Director 需聚合全局视图 |

**非目标（明确不做）**：

- 不引入 Redis/etcd 等外部依赖（用户决策 5）
- 不改造 `DirectorEngine._run_loop` 的子任务逻辑（阶段 1.3 已加异常容错，复用即可）
- 不改 `Election` 算法（阶段 1.1 已接入，本设计仅复用其 `ElectionResult`）
- 不在本阶段实现 N>10 的大规模扩展（用户决策 3）

**关键观察**：阶段 1.1 已在 `_check_director_health`（worker_adapter.py:1535-1559）接入 `Election.run()`，但因 `self._director_manager = None`（worker_adapter.py:266），胜出后 **无法真正启动 director**，仍 fallback 到 `_autonomous.enter()`。这是阶段 3 必须填补的差距。

#### 子进程模式 vs 嵌入式模式对比

| 维度 | 子进程模式（当前） | 嵌入式模式（本设计） |
|---|---|---|
| Director 运行载体 | 独立 `python -m director_cli` 子进程 | worker 进程内的 asyncio 协程 |
| 启动开销 | spawn 子进程 + import + init ≈ 500ms-1s | `create_task` + `start()` ≈ <100ms |
| 崩溃恢复 | `_watchdog` 检测 `poll()` + 重启子进程（10s 周期） | 协程异常被 `try/except` 捕获，`_loop_task` 退出触发 `deactivate` + 重新 `Election` |
| 资源占用 | 独立 Python 解释器，内存 ~30-50MB/实例 | 共享 worker 解释器，增量 <5MB |
| 僵尸风险 | **高**：子进程异常退出仍持 `director.lock`（P5 根因） | **无**：协程取消即释放锁（`stop()` 内 `_release_mutex_lock`） |
| 与 worker 隔离 | 进程级隔离（强） | asyncio.Task 级隔离（中，需 TaskGroup 设计） |
| 跨实例迁移 | 需杀子进程 + 清锁 + 远端 spawn | `Election.run()` 胜出 → `activate(epoch)` 即可迁移 |
| 调试便利 | `director.log` 独立文件，可单独 kill | 与 worker 日志混合，需 `pid` 字段区分 |
| 现有 API 复用 | `DirectorEngine` 完整复用 | `DirectorEngine` 完整复用（**组合**而非继承） |

**结论**：嵌入式在僵尸风险、迁移速度、资源占用上全面优于子进程模式，唯一代价是隔离性降低（需 TaskGroup 设计弥补）。

## 三、设计方案

### 3.1 EmbeddedDirector 类设计

#### 3.1.1 设计原则：组合而非继承

`DirectorEngine` 已是成熟类（~840 行，含 epoch 递增 / 互斥锁 / 心跳监督 / 轮次推进 / 信任分 / flush pending），**继承会引入 `_running` / `_loop_task` 等状态字段的覆盖歧义**。本设计采用 **组合（包装）模式**：

- `EmbeddedDirector` 内部持有一个 `DirectorEngine` 实例，委托 `start/stop/_run_loop` 给后者
- `EmbeddedDirector` 仅新增 **standby 状态机 + epoch 续约 + 降级回调**
- `DirectorEngine` 代码 **零改动**，保证阶段 1+2 的稳定性不受影响

#### 3.1.2 类签名与关键属性

```python
# 新文件：teage_liu/multiagent/embedded_director.py
from __future__ import annotations

import asyncio
import logging
from dataclasses import dataclass
from datetime import datetime, timezone
from pathlib import Path
from typing import Literal

from teage_liu.multiagent.director_engine import DirectorEngine
from teage_liu.multiagent.election import Election, ElectionResult

logger = logging.getLogger(__name__)


DirectorState = Literal["standby", "activating", "active", "deactivating", "faulted"]


@dataclass
class EmbeddedDirectorStatus:
    """嵌入式 Director 状态快照（供 /director/status 端点返回）。"""
    state: DirectorState
    epoch: int
    last_tick: str  # ISO 时间，来自 director.md
    task_failure_counts: dict[str, int]
    activated_at: str  # 上次 activate 时间
    deactivated_at: str  # 上次 deactivate 时间
    fault_reason: str  # faulted 时的原因


class EmbeddedDirector:
    """嵌入式 Director：作为 worker 协程运行，由选举决定是否激活。

    生命周期：
        worker.start() → EmbeddedDirector(state=standby)
        Election.run().won → activate(epoch) → state=active → DirectorEngine._run_loop 运行
        主 director 恢复 / 自身连续失败 → deactivate() → state=standby
        worker.stop() → finalize() → 释放 DirectorEngine 资源

    与 DirectorEngine 的关系：组合。EmbeddedDirector 持有 DirectorEngine 实例，
    委托 start/stop，不修改其内部状态机。

    与 WorkerAdapter 的关系：聚合。WorkerAdapter 持有 EmbeddedDirector 引用，
    在 _check_director_health 胜出分支调用 activate()。
    """

    def __init__(
        self,
        bb_root: Path,
        config: dict,
        agent_id: str,
        director_engine: DirectorEngine | None = None,
    ):
        self._bb_root = bb_root
        self._config = config
        self._agent_id = agent_id
        # 组合 DirectorEngine（允许外部注入，便于测试 mock）
        self._engine = director_engine or DirectorEngine(
            bb_root=bb_root,
            config=config,
            agent_id=agent_id,
        )
        self._state: DirectorState = "standby"
        self._activated_at: str = ""
        self._deactivated_at: str = ""
        self._fault_reason: str = ""
        self._loop_watcher: asyncio.Task | None = None  # 监听 _engine._loop_task 退出
        self._lock = asyncio.Lock()  # 保护 activate/deactivate 临界区

    @property
    def state(self) -> DirectorState:
        return self._state

    @property
    def engine(self) -> DirectorEngine:
        """暴露内部 DirectorEngine（供 status 端点 / 测试访问）。"""
        return self._engine
```

#### 3.1.3 关键方法清单

| 方法 | 职责 | 调用方 |
|---|---|---|
| `activate(epoch: int) -> bool` | standby → active：调 `engine.start()` + 启动 `_loop_watcher` | WorkerAdapter._check_director_health 胜出分支 |
| `deactivate(reason: str) -> None` | active → standby：调 `engine.stop()` + 取消 watcher | 主 director 恢复 / 自身失败 / worker.shutdown |
| `finalize() -> None` | worker 关闭时无条件释放资源 | WorkerAdapter.stop |
| `status() -> EmbeddedDirectorStatus` | 返回状态快照 | multiagent_routes /director/status |
| `_watch_loop_task() -> None` | 监听 `engine._loop_task` 退出，触发 `deactivate(faulted)` | activate 内部 create_task |

### 3.2 状态机

```
                    worker.start()
                          │
                          ▼
                    ┌───────────┐
                    │  standby  │ ◄──────────────────────────────────┐
                    │ (默认)    │                                     │
                    └─────┬─────┘                                     │
                          │ Election.run().won=True                   │
                          │ (worker_adapter._check_director_health    │
                          │  检测到原 director offline)                 │
                          ▼                                           │
                    ┌───────────┐  engine.start() 失败                │
              ┌─────│activating │─────────────────────────┐          │
              │     └─────┬─────┘                         ▼          │
              │           │ engine.start() 成功      ┌─────────┐      │
              │           │ + _loop_watcher 启动     │ faulted │      │
              │           ▼                          └────┬────┘      │
              │     ┌───────────┐                          │           │
              │     │  active   │  主 director 恢复        │           │
              │     │ _run_loop │  (检测到更高 epoch        │           │
              │     │  运行中    │   或本地心跳新鲜)         │           │
              │     └─────┬─────┘                          │           │
              │           │ deactivate("recovered")       │           │
              │           │ 或 _loop_watcher 触发         │           │
              │           │   deactivate("loop_exited")   │           │
              │           ▼                               │           │
              │     ┌─────────────┐                     │           │
              │     │deactivating │                     │           │
              │     │ engine.stop │                     │           │
              │     └──────┬──────┘                     │           │
              │            │ stop 完成                  │           │
              │            ▼                            │           │
              │      (回到 standby)─────────────────────┼───────────┤
              │                                         │           │
              └─────────────────────────────────────────┘           │
                  activate 失败自动 fallback                        │
                                                                        │
                  faulted → 修复后 worker 重启或手动 reset ─────────────┘
```

#### 状态转换条件与触发动作

| 当前状态 | 事件 | 目标状态 | 触发动作 |
|---|---|---|---|
| standby | `Election.run().won=True` | activating | 调 `activate(epoch)` |
| activating | `engine.start()` 成功 | active | 启动 `_loop_watcher` |
| activating | `engine.start()` 抛异常（如 `LockAcquisitionError`） | faulted | 记录 `_fault_reason`，不重试（避免崩溃风暴） |
| active | `_loop_watcher` 检测到 `engine._loop_task` 退出 | deactivating | 调 `deactivate("loop_exited")` |
| active | WorkerAdapter 检测到主 director 恢复（更高 epoch） | deactivating | 调 `deactivate("recovered")` |
| active | `worker.stop()` 被调用 | deactivating | 调 `deactivate("worker_shutdown")` |
| deactivating | `engine.stop()` 完成 | standby | 清理 watcher，重置 `_fault_reason` |
| faulted | 手动 reset 或 worker 重启 | standby | 清理状态（需运维介入） |

**关键约束**：

- `activate` / `deactivate` 用 `asyncio.Lock` 串行化，避免并发触发状态竞争
- `faulted` 状态 **不自动重试**，避免锁竞争风暴（与 `LocalDirectorManager._max_restarts=3` 一致的保守策略）
- 从 `active` 回到 `standby` 后，下次 `_check_director_health` 周期可再次触发 `Election.run()`，实现"故障恢复后再当选"

### 3.3 启动 / 接管 / 降级流程

#### 3.3.1 worker 启动时：EmbeddedDirector 初始化为 standby

```
worker.start()
    │
    ├─ 1. _load_state_on_start()
    ├─ 2. _register() (agent_card)
    ├─ 3. _heartbeat_loop 启动
    ├─ 4. _director_monitor_loop 启动
    │      └─ 周期调 _check_director_health()
    └─ 5. EmbeddedDirector 已在 __init__ 时构造，state=standby
         （不启动 _run_loop，仅持有 DirectorEngine 实例）
```

**关键**：`EmbeddedDirector.__init__` 不调 `engine.start()`，避免 worker 启动时立即抢锁。仅当选举胜出后才激活。

#### 3.3.2 检测到超时 → 选举胜出 → activate

```
_director_monitor_loop (worker_adapter.py:775)
    │
    ▼
_check_director_health()
    │
    ├─ 读 director.md → age > timeout (30s)
    │
    ├─ director_v2_enabled=True 分支：
    │   ├─ Election(bb_root, agent_id, config).run()
    │   │
    │   ├─ result.won=True
    │   │   ├─ 【本设计改动点】调 self._director_manager.activate(result.epoch)
    │   │   │      （_director_manager 现为 EmbeddedDirector 实例）
    │   │   ├─ activate 内部：
    │   │   │   ├─ state: standby → activating
    │   │   │   ├─ engine.start()  # 获取 director.lock + 递增 epoch + broadcast_started + create_task(_run_loop)
    │   │   │   ├─ create_task(_loop_watcher)  # 监听 engine._loop_task 退出
    │   │   │   └─ state: activating → active
    │   │   └─ return "healthy"  # 自己接管后视为健康
    │   │
    │   └─ result.won=False
    │       ├─ 等待 election_wait_seconds (5s)
    │       └─ 递归 _check_director_health()  # 等胜者心跳
    │
    └─ 旧 fallback（director_v2_enabled=False 或选举异常）：
        └─ _autonomous.enter()  # 保留原行为
```

#### 3.3.3 主 director 恢复 → deactivate 回到 standby

主 director（其他实例）恢复后，其 `director.md` 的 `current_epoch` 会高于本机，且 `last_director_tick` 新鲜。本机在下次 `_check_director_health` 周期检测到：

```
_check_director_health()
    │
    ├─ 读 director.md（本机嵌入式 director 仍在写）
    │   └─ 但同时通过 A2A read_director_md 查询其他实例（任务 3.R2 范围，本设计预留接口）
    │
    ├─ 若检测到远程实例 epoch > 本机 epoch 且远程心跳新鲜：
    │   ├─ 本机为"次优" director，应降级
    │   ├─ 调 self._director_manager.deactivate(reason="recovered_by_remote_epoch")
    │   │   ├─ state: active → deactivating
    │   │   ├─ engine.stop()  # cancel _loop_task + 释放 director.lock
    │   │   ├─ cancel _loop_watcher
    │   │   └─ state: deactivating → standby
    │   └─ return "healthy"  # 远程 director 接管，视为健康
    │
    └─ 否则继续 active 运行
```

**注**：跨实例 director 心跳查询是任务 3.R2 的范围，本设计在 `EmbeddedDirector` 预留 `check_remote_director_epoch()` 接口，具体实现由 3.R2 文档细化。

#### 3.3.4 异常时降级到 LocalDirectorManager（fallback）

当 `EmbeddedDirector` 进入 `faulted` 状态（如 `engine.start()` 抛 `LockAcquisitionError` 连续失败），可选降级到子进程模式：

```
EmbeddedDirector.state == "faulted"
    │
    ├─ 若 config.multiagent.worker.fallback_to_local_manager=True（默认 False）：
    │   ├─ 创建 LocalDirectorManager 实例
    │   ├─ 调 local_manager.start()  # spawn director_cli 子进程
    │   └─ 记录 audit：embedded_faulted_fallback_to_local
    │
    └─ 否则保持 faulted，等待运维介入或下次选举周期重试
```

**推荐默认关闭 fallback_to_local_manager**（见决策 D2），避免双模式混用增加复杂度。

### 3.4 asyncio.TaskGroup 隔离策略

#### 3.4.1 隔离目标

worker 进程内同时运行两组循环：

| 循环组 | 任务 | 阻塞特征 |
|---|---|---|
| worker 主循环 | `_heartbeat_loop` / `_collab_poll_loop` / `_idle_check_loop` / `_director_monitor_loop` | LLM 调用可能阻塞 10-30s（`_trigger_urgent_llm`） |
| director 循环 | `DirectorEngine._run_loop`（6 个子任务，1s tick） | 文件 IO + LLM 仲裁（`_arbitrate_conflicts` 当前空实现） |

**隔离要求**：
1. director 循环异常 **不得** 取消 worker 主循环
2. worker 主循环异常 **不得** 取消 director 循环（director 应能继续监督 worker 心跳）
3. worker 关闭时 **先** cancel director 任务，**再** cancel 自己（保证 director.lock 先释放）

#### 3.4.2 方案选择：独立 create_task + 互相监听

项目代码风格（lifespan.py:313-327）大量使用 `asyncio.create_task` + `BackgroundTaskRegistry`，且 `DirectorEngine.start()` 内部已用 `create_task(self._run_loop)`。采用 `asyncio.TaskGroup`（Python 3.11+）会与现有风格冲突，且 TaskGroup 的"任一异常取消全部"语义不符合隔离要求。

**本设计采用**：独立 `create_task` + `try/except` 包裹 + `_loop_watcher` 监听，语义上等价于"宽松版 TaskGroup"：

```python
# WorkerAdapter.start() 内（概念，实际改动见 §4.1）
# worker 主循环任务组
self._heartbeat_task = asyncio.create_task(self._heartbeat_loop(interval))
self._collab_poll_task = asyncio.create_task(self._collab_poll_loop())
self._director_monitor_task = asyncio.create_task(self._director_monitor_loop())

# director 任务由 EmbeddedDirector.activate() 内部 create_task
# （不放入 worker 的 task 组，保证隔离）
```

#### 3.4.3 _loop_watcher 实现

`_loop_watcher` 监听 `engine._loop_task` 退出，触发 `deactivate`：

```python
async def _watch_loop_task(self) -> None:
    """监听 DirectorEngine._loop_task 退出，触发 deactivate。

    _loop_task 退出原因：
    - 正常 cancel（worker.stop 触发 engine.stop → cancel _loop_task）
    - _run_loop 内 _running=False（连续失败 10 次，阶段 1.3）
    - _run_loop 抛未捕获异常（被 _run_loop 内 try/except 兜住，不应到达此处）
    """
    try:
        if self._engine._loop_task is not None:
            await self._engine._loop_task
    except asyncio.CancelledError:
        # 正常关闭路径，不算 fault
        logger.info("DirectorEngine._loop_task 被 cancel（正常关闭）")
    except Exception as e:
        logger.exception("DirectorEngine._loop_task 异常退出: %s", e)
        await self.deactivate(reason=f"loop_exited_with_exception: {e}")
        return
    # _loop_task 正常结束（_running=False）→ 视为 fault，需 deactivate
    if self._state == "active":
        await self.deactivate(reason="loop_exited_normally_but_unexpected")
```

#### 3.4.4 关闭顺序

worker 关闭时（`WorkerAdapter.stop`），取消顺序：

```
worker.stop()
    │
    ├─ 1. self._running = False
    │
    ├─ 2. embedded_director.finalize()
    │      ├─ 若 state=active：deactivate("worker_shutdown")
    │      │   └─ engine.stop()  # cancel _loop_task + 释放 director.lock
    │      └─ 取消 _loop_watcher
    │
    ├─ 3. cancel _heartbeat_task / _director_monitor_task（worker 自己的）
    │
    ├─ 4. cancel _collab_poll_task / _idle_check_task
    │
    └─ 5. _release_my_locks + 更新 agent_card offline
```

**关键**：先 `finalize` director（释放 `director.lock`），再 cancel worker 任务，保证其他实例可立即通过选举接管。

### 3.5 status.json 跨实例同步（方案 Y）

#### 3.5.1 现状差距

A2A gateway（a2a_gateway.py:116-133）已暴露的方法：`list_agents` / `read_messages` / `read_director_md` / `read_file` / `director_broadcast` / `agent_message` / `heartbeat`。

**缺失**：无 `read_status_json` 方法。`Election._query_remote_directors`（election.py:153-161）当前用 `call_all_endpoints("read_director_md", {})` 查询，但 director.md 不含 `status.json` 的 `current_turn` / `locks` / `director` 字段。

#### 3.5.2 同步策略：定期拉取为主 + 关键变更即时广播

**纯实时广播** 的问题：N=10 时每次状态变更触发 10 次 A2A 调用，放大网络负载。
**纯定期拉取** 的问题：延迟大（如 5s 周期则最大延迟 5s）。

**折中策略**：

| 触发场景 | 同步方式 | 延迟目标 |
|---|---|---|
| Director epoch 变更（选举胜出） | 即时广播（复用 `director_broadcast` A2A 方法） | <1s |
| Agent 状态变更（offline/degraded） | 即时广播 | <1s |
| `current_turn` 推进 | 定期拉取（Director 周期 5s 拉取所有端点） | ≤5s |
| `locks` 变更 | 定期拉取 | ≤5s |
| `status.json` 全量同步 | 定期拉取（兜底） | ≤5s |

#### 3.5.3 实现方案

**新增 A2A 方法** `read_status_json`（a2a_gateway.py methods 字典新增）：

```python

**DirectorEngine._run_loop 新增子任务** `_sync_cross_instance_status`（周期 5s）：

#### 3.5.4 最终一致性容忍

方案 Y 接受短暂不一致：

- `current_turn` 跨实例最多差 5s：可接受（turn_timeout 默认 30s，5s 误差不影响轮次推进）
- `locks` 跨实例最多差 5s：**不可接受**（锁冲突需强一致）→ 锁状态仍由 `FileLock` 跨进程锁保证（阶段 1.2），status.json 的 `locks` 字段仅作展示，不作为锁判定的权威源

### 3.6 agent_card 跨实例视图聚合

#### 3.6.1 现状

每实例 `agents/{agent_id}.md` 仅本地视图。Director 监督 worker 心跳时（`_check_worker_heartbeats`，director_engine.py:502）只读本地 agent_card，无法感知远程实例的 agent 状态。

#### 3.6.2 聚合方案

**复用已有 A2A 方法 `list_agents`**（a2a_gateway.py:117），无需新增方法：

```
Director._sync_cross_instance_status (周期 5s)
    │
    ├─ A2A call_all_endpoints("list_agents", {})
    │   ├─ worker1 返回 [{agent_id, status, trust_score, last_heartbeat}, ...]
    │   ├─ worker2 返回 [...]
    │   └─ workerN 返回 [...]
    │
    ├─ 聚合到本地 agent_cards.json（新文件，全局视图）
    │   {
    │     "teagent-lu": {source: "worker1", status: "active", trust_score: 100, ...},
    │     "teagent-liu-2": {source: "worker2", status: "active", trust_score: 95, ...},

    │   }
    │

- Director `_check_worker_heartbeats` 时感知远程 agent 状态
- `/director/status` 端点返回全局视图供运维查看

#### 3.6.3 冲突处理

同一 agent 可能被多个实例上报（如 agent 迁移中）：

- 取 `last_heartbeat` 最新的那条
- `source` 字段记录来源实例，便于追溯

## 五、关键代码骨架

### 5.1 EmbeddedDirector 完整骨架

```python
# 新文件：teage_liu/multiagent/embedded_director.py
"""嵌入式 Director：作为 worker 协程运行，由选举决定是否激活。

阶段 3 任务 3.R1 产出。配套文档：docs/plans/2026-07-31-嵌入式Director设计.md

设计要点：
- 组合 DirectorEngine（不继承），零改动复用阶段 1+2 成果
- standby → active → standby 状态机，activate/deactivate 用 Lock 串行化
- _loop_watcher 监听 engine._loop_task 退出，触发自动 deactivate
- faulted 状态不自动重试（避免锁竞争风暴），需运维介入或下次选举周期
"""
from __future__ import annotations

import asyncio
import logging
from dataclasses import dataclass, field
from datetime import datetime, timezone
from pathlib import Path
from typing import Literal

from teage_liu.multiagent.director_engine import DirectorEngine
from teage_liu.multiagent.exceptions import LockAcquisitionError

logger = logging.getLogger(__name__)


DirectorState = Literal["standby", "activating", "active", "deactivating", "faulted"]


def _now_iso() -> str:
    return datetime.now(timezone.utc).isoformat()


@dataclass
class EmbeddedDirectorStatus:
    """嵌入式 Director 状态快照。"""
    state: DirectorState
    epoch: int
    last_tick: str
    task_failure_counts: dict[str, int]
    activated_at: str
    deactivated_at: str
    fault_reason: str


class EmbeddedDirector:
    """嵌入式 Director：作为 worker 协程运行。

    生命周期：standby → (选举胜出) → active → (主 director 恢复/自身失败) → standby
    与 DirectorEngine 组合，与 WorkerAdapter 聚合。
    """

    def __init__(
        self,
        bb_root: Path,
        config: dict,
        agent_id: str,
        director_engine: DirectorEngine | None = None,
    ):
        self._bb_root = bb_root
        self._config = config
        self._agent_id = agent_id
        self._engine = director_engine or DirectorEngine(
            bb_root=bb_root,
            config=config,
            agent_id=agent_id,
        )
        self._state: DirectorState = "standby"
        self._activated_at: str = ""
        self._deactivated_at: str = ""
        self._fault_reason: str = ""
        self._loop_watcher: asyncio.Task | None = None
        self._lock = asyncio.Lock()

    @property
    def state(self) -> DirectorState:
        return self._state

    @property
    def engine(self) -> DirectorEngine:
        return self._engine

    async def activate(self, epoch: int) -> bool:
        """standby → active：启动 DirectorEngine._run_loop。

        Args:
            epoch: 选举胜出的 epoch（由 Election.run() 返回）

        Returns:
            True 表示激活成功；False 表示激活失败（已进入 faulted）
        """
        async with self._lock:
            if self._state != "standby":
                logger.warning(
                    "activate 被拒绝：当前 state=%s（需 standby）", self._state
                )
                return False

            self._state = "activating"
            try:
                # DirectorEngine.start() 内部：
                #   _acquire_mutex_lock + _increment_epoch + _broadcast_started + create_task(_run_loop)
                # 注：engine.start() 会再次 _increment_epoch（基于 director.md），
                #     与传入 epoch 可能差 1。可接受：以 engine._current_epoch 为准。
                await self._engine.start()
                # 启动 watcher 监听 _loop_task 退出
                if self._engine._loop_task is not None:
                    self._loop_watcher = asyncio.create_task(self._watch_loop_task())
                self._state = "active"
                self._activated_at = _now_iso()
                self._fault_reason = ""
                logger.info(
                    "EmbeddedDirector 已激活 agent=%s epoch=%s",
                    self._agent_id, self._engine._current_epoch,
                )
                return True
            except LockAcquisitionError as e:
                # 锁被持有且无法强抢（原 director 仍活跃）
                logger.warning("activate 获取 director.lock 失败: %s", e)
                self._state = "faulted"
                self._fault_reason = f"lock_acquisition_failed: {e}"
                self._deactivated_at = _now_iso()
                return False
            except Exception as e:
                logger.exception("activate 异常: %s", e)
                self._state = "faulted"
                self._fault_reason = f"activate_exception: {e}"
                self._deactivated_at = _now_iso()
                return False

    async def deactivate(self, reason: str) -> None:
        """active → standby：停止 DirectorEngine 并释放锁。"""
        async with self._lock:
            if self._state not in ("active", "activating", "faulted"):
                return

            self._state = "deactivating"
            try:
                await self._engine.stop()  # cancel _loop_task + _release_mutex_lock
            except Exception as e:
                logger.warning("engine.stop 异常: %s", e)

            if self._loop_watcher is not None and not self._loop_watcher.done():
                self._loop_watcher.cancel()
                try:
                    await self._loop_watcher
                except asyncio.CancelledError:
                    pass
                self._loop_watcher = None

            self._state = "standby"
            self._deactivated_at = _now_iso()
            logger.info("EmbeddedDirector 已降级 reason=%s", reason)

    async def finalize(self) -> None:
        """worker 关闭时无条件释放资源。"""
        if self._state in ("active", "activating"):
            await self.deactivate(reason="worker_shutdown")
        elif self._state == "faulted":
            # faulted 状态下 engine 可能未正确启动，仍尝试 stop 清理
            try:
                await self._engine.stop()
            except Exception:
                pass
            self._state = "standby"

    async def _watch_loop_task(self) -> None:
        """监听 DirectorEngine._loop_task 退出，触发 deactivate。"""
        try:
            if self._engine._loop_task is not None:
                await self._engine._loop_task
        except asyncio.CancelledError:
            # 正常关闭路径（engine.stop 主动 cancel）
            logger.info("DirectorEngine._loop_task 被 cancel（正常关闭）")
            return
        except Exception as e:
            logger.exception("DirectorEngine._loop_task 异常退出: %s", e)
            if self._state == "active":
                await self.deactivate(reason=f"loop_exception: {e}")
            return
        # _loop_task 正常结束（_running=False，连续失败 10 次）
        if self._state == "active":
            logger.warning("DirectorEngine._loop_task 正常退出但 state=active，触发降级")
            await self.deactivate(reason="loop_exited_normally")

    def status(self) -> EmbeddedDirectorStatus:
        """返回状态快照（同步，不触发 IO）。"""
        return EmbeddedDirectorStatus(
            state=self._state,
            epoch=self._engine._current_epoch,
            last_tick="",  # 由路由层读 director.md 填充
            task_failure_counts=dict(self._engine._task_failure_counts),
            activated_at=self._activated_at,
            deactivated_at=self._deactivated_at,
            fault_reason=self._fault_reason,
        )
```

## 六、风险与缓解

| # | 风险 | 概率 | 影响 | 缓解措施 |
|---|---|---|---|---|
| R1 | 嵌入式 Director 与 worker 主循环互相拖累（共享 event loop） | 中 | worker LLM 调用延迟退化 / director tick 卡顿 | (1) `_run_loop` 子任务异常容错（阶段 1.3 已做）；(2) director 的 LLM 仲裁（`_arbitrate_conflicts`）当前空实现，未来接入时用独立 `asyncio.Semaphore` 限流；(3) `_trigger_urgent_llm` 已用 `_llm_lock` 串行，与 director `_run_loop` 不共享锁 |
| R2 | 选举算法误判导致双 Director（脑裂） | 中 | 全局状态冲突，director.md 互相覆盖 | (1) `DirectorEngine._acquire_mutex_lock` 的 `director.lock` 跨进程互斥（portalocker.LOCK_EX）保证同机唯一；(2) epoch 机制：旧 director 写入被 `_current_epoch` 检查拒绝；(3) 跨机时 `Election._is_director_stale` 用 30s lease，超时才抢占；(4) **建议引入 lease 续约**（见决策 D5） |
| R3 | 旧 LocalDirectorManager 与新 EmbeddedDirector 共存冲突 | 低 | 两者同时尝试获取 `director.lock`，后者失败 | (1) 单实例内由 `director_v2_enabled` 决定只启用一种；(2) `multiagent_routes.py` 的 `/director/start` 按 `director_v2_enabled` 分流；(3) `lifespan` 关闭段仅 `director_v2_enabled=False` 时清理子进程 |
| R4 | status.json 跨实例同步延迟导致短暂不一致 | 中 | Director 决策基于过期数据（如 agent 状态） | (1) 关键变更（epoch / agent offline）即时广播；(2) `current_turn` / `locks` 仅作展示，权威源仍是本地文件 + FileLock；(3) 同步周期 5s 可配置调优 |
| R5 | `_loop_watcher` 漏检 `_loop_task` 退出（如 `engine.start()` 后 `_loop_task` 立即异常） | 低 | director 静默死亡，无人感知 | (1) `_loop_watcher` 在 `activate` 内 `engine.start()` 成功后立即 `create_task`；(2) `_check_director_health` 周期（10s）兜底：若 director 心跳超时仍会触发 Election；(3) `engine._loop_task` 为 None 时 watcher 直接 return 并 log |
| R6 | `EmbeddedDirector.faulted` 后无法自愈 | 中 | 故障实例永久停摆，需运维介入 | (1) faulted 状态下次 `_check_director_health` 周期可重新触发 Election（standby 才能 activate，faulted 需先 reset）；(2) 提供 `POST /director/reset` 端点手动重置 faulted → standby；(3) 长期方案：watchdog 协程检测 faulted 持续 >5min 自动 reset |
| R7 | 跨实例 A2A 调用风暴（N=10 时 sync_status 触发 10 次调用/5s） | 低 | 网络拥塞，A2A gateway 限流（默认 100/s）触发 429 | (1) `call_all_endpoints` 已用 `asyncio.gather` 并发，单次同步总耗时 ≈ 单端点延迟；(2) `RateLimiter` 默认 100/s，5s 周期 × 10 端点 = 2/s 远低于上限；(3) 可配置 `sync_status_interval_seconds` 调大周期 |
| R8 | 嵌入式 Director 崩溃导致 worker 进程崩溃 | 低 | 整个实例不可用 | (1) `_run_loop` 内 try/except 兜住所有子任务异常（阶段 1.3）；(2) `_loop_watcher` 用 try/except 包裹，异常触发 `deactivate` 而非传播；(3) `activate` 内 `engine.start()` 异常被 catch，进入 faulted 而非崩溃 worker |

### 决策 D2：是否保留 LocalDirectorManager 作为永久 fallback？

### 决策 D3：status.json 同步策略

| 选项 | 描述 | 延迟 | A2A 调用量（N=10） |
|---|---|---|---|
| A. 实时广播 | 任何 status 变更即时广播到所有端点 | <1s | 每次变更 × 10 端点 |
| B. 定期拉取 | Director 周期拉取所有端点 status | ≤5s | 10 端点 / 5s = 2/s |
| C. 混合（推荐） | 关键变更广播 + 定期拉取兜底 | <1s（关键）/ ≤5s（普通） | 2/s + 偶发广播 |

**推荐**：C（混合）

**理由**：
1. 纯实时广播在 N=10 时放大网络负载（每次 agent 状态变更触发 10 次调用）
2. 纯定期拉取对关键变更（epoch / agent offline）延迟过大
3. 混合策略对关键变更保证 <1s 延迟，对普通变更容忍 5s 延迟，平衡性能与一致性
4. 复用已有 `director_broadcast` A2A 方法（a2a_gateway.py:129），无需新增广播通道

### 决策 D5：是否引入 lease 续约机制防止双 Director？

| 选项 | 描述 | 实现 |
|---|---|---|
| A. 引入 lease（推荐） | Director 每 10s 续约 `director.md.lease_until`，过期则可被抢占 | DirectorEngine._update_director_tick 内追加 lease_until 字段 |

**理由**：
1. 现有 30s timeout 在跨机网络分区时可能导致双 Director（A 认为 B 超时，B 认为 A 超时，同时选举）
2. lease 机制：Director 每 10s 续约 `lease_until = now + 30s`，其他实例仅当 `lease_until` 过期才抢占，提供显式的"租约"语义
3. 实现成本低：`_update_director_tick` 已每秒更新 `last_director_tick`，追加 `lease_until` 字段即可
4. 与 `Election._is_director_stale` 兼容：优先检查 `lease_until`，无则 fallback 到 `last_tick`

### 决策 D6：faulted 状态的自愈策略

| 选项 | 描述 | 风险 |
|---|---|---|
| A. 不自愈，需运维介入 | faulted 永久，直到手动 reset | 故障实例停摆 |
| B. 下次选举周期自动 reset（推荐） | faulted → standby，可再次被 Election 激活 | 可能锁竞争循环 |
| C. 延迟自愈（5min 后 reset） | faulted 持续 5min 后自动回 standby | 平衡稳定性与自愈 |

**推荐**：C（延迟自愈）

**理由**：
1. A 太保守，B 太激进（锁竞争风暴风险）
2. C 在故障后给系统 5min 缓冲期，让原 director 恢复或被其他实例接管，再尝试自愈
3. 可配置 `faulted_auto_reset_seconds`（默认 300s）
