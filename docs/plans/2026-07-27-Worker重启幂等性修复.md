# Worker 重启幂等性修复 Implementation Plan

> **For agentic workers:** Use the java-dev-skills workflow to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 彻底解决 WorkerAdapter 重启后历史协作消息被重复处理的问题，覆盖用户广播、intervention directive、普通队列消息、A2A 任务四条副作用路径，建立跨重启的幂等性保证。

**Architecture:** 分三层修复：Layer A 新建 `WorkerStateStore` 模块负责状态持久化原子读写（`agents/{agent_id}.state.json`）；Layer B 在 WorkerAdapter 启动时扫描 `collaboration.md` + `messages.md` 历史构建幂等集（`_responded_request_seqs` / `_processed_msg_seqs` / `_executed_op_ids`），首次升级无 state 文件时自动重建；Layer C 在所有副作用路径（`_handle_request` / `_handle_directive` / `_trigger_urgent_llm` / A2A 任务执行）增加幂等检查，并在副作用完成后立即持久化状态。配置项支持热更新，遵循项目"所有改进配置需支持 config.yaml 热更新"硬约束。

**Tech Stack:** Python 3.11+ / asyncio / pytest / pytest-asyncio / aiofiles / PyYAML

## Global Constraints

- 所有改动必须保持现有测试通过（执行 `pytest tests/multiagent/` 验证回归）
- 遵循 TDD：先写失败测试 → 验证失败 → 最小实现 → 验证通过 → 提交

## 问题全景

### 用户报告的问题
Worker 重启后，已完成的用户广播协作被再次读取并再次回复。

### 同类问题（一并修复）

| 路径 | 副作用 | 当前防护 | 修复目标 |
|---|---|---|---|
| 用户广播（`from=user, type=request`）| 立即触发 LLM + 写 response 消息 | 仅 `message_id` 写入去重 | 启动时构建 `_responded_request_seqs`，处理前检查 |
| intervention directive | 立即触发 LLM | 无 | 启动时构建 `_processed_urgent_seqs`，处理前检查 |
| 普通队列消息（relay/response/result/ordering directive）| 进入 `_normal_queue`，下次 LLM 调用时注入上下文 | 无 | 启动时构建 `_processed_msg_seqs`，入队前检查 |
| A2A 任务（`messages.md` 中 `task_op_id`）| 执行任务 + 写 result 消息 | 无（项目记忆中计划但未实现） | 启动时构建 `_executed_op_ids`，执行前检查 |

### 根因
`WorkerAdapter.__init__` 中 `_last_collab_seq = 0` 是内存变量，无持久化。重启后 `_poll_collab_once()` 以 `seq > 0` 为过滤条件，导致全部历史消息被当作新消息重新处理。

### 与既有设计的关系
项目记忆中已有"A2A `_executed_op_ids`"设计点，但代码中**未实现**（已核实 `a2a_gateway.py` 和 `director_engine.py`）。本方案将这一设计模式系统化扩展到所有副作用路径。

```python
# teage_liu/multiagent/worker_state.py
"""Worker 状态持久化模块。

负责跨重启的"已处理消息"状态读写，支持幂等性保证。

设计原则：
- 原子写入：先写 .tmp 再 os.replace（复用 blackboard.atomic_write）
- 损坏降级：JSON 解析失败时返回默认空状态，记录 warning，不抛异常
- 路径隔离：每个 agent_id 独立 state 文件，避免并发写入冲突
- set <-> list 转换：JSON 不支持 set，序列化时转 list，反序列化时转 set
"""
from __future__ import annotations

import json
import logging
from dataclasses import asdict, dataclass, field
from datetime import datetime, timezone
from pathlib import Path
from typing import Any

from teage_liu.multiagent.blackboard import atomic_write, validate_path_safety
from teage_liu.multiagent.exceptions import PathSafetyError, WorkerStateError

logger = logging.getLogger(__name__)


def _now_iso() -> str:
    return datetime.now(timezone.utc).isoformat()


@dataclass
class WorkerState:
    """Worker 跨重启状态。

    字段说明：
    - last_collab_seq: 已处理的协作消息最大 seq（兜底，主要靠下面的精确集合）
    - responded_request_seqs: 本 agent 已写过 response 的 request seq 集合
    - processed_msg_seqs: 本 agent 已处理过的协作消息 seq 集合（防止重复入队）
    - processed_urgent_seqs: 本 agent 已处理过的紧急消息 seq 集合（intervention directive）
    - executed_op_ids: 本 agent 已执行过的 A2A 任务 op_id 集合
    - last_updated_at: 最后更新时间（ISO 格式，便于排查）
    """
    last_collab_seq: int = 0
    responded_request_seqs: set[int] = field(default_factory=set)
    processed_msg_seqs: set[int] = field(default_factory=set)
    processed_urgent_seqs: set[int] = field(default_factory=set)
    executed_op_ids: set[str] = field(default_factory=set)
    last_updated_at: str = ""

    def to_dict(self) -> dict:
        """转可 JSON 序列化的 dict（set → list）。"""
        d = asdict(self)
        d["responded_request_seqs"] = sorted(self.responded_request_seqs)
        d["processed_msg_seqs"] = sorted(self.processed_msg_seqs)
        d["processed_urgent_seqs"] = sorted(self.processed_urgent_seqs)
        d["executed_op_ids"] = sorted(self.executed_op_ids)
        return d

    @classmethod
    def from_dict(cls, data: dict) -> "WorkerState":
        """从 dict 构建（list → set，兼容字段缺失）。"""
        return cls(
            last_collab_seq=int(data.get("last_collab_seq", 0)),
            responded_request_seqs=set(data.get("responded_request_seqs", [])),
            processed_msg_seqs=set(data.get("processed_msg_seqs", [])),
            processed_urgent_seqs=set(data.get("processed_urgent_seqs", [])),
            executed_op_ids=set(data.get("executed_op_ids", [])),
            last_updated_at=str(data.get("last_updated_at", "")),
        )


class WorkerStateStore:
    """Worker 状态持久化（按 agent_id 隔离）。

    状态文件路径：{bb_root}/agents/{agent_id}.state.json
    """

    def __init__(self, bb_root: Path, agent_id: str) -> None:
        self._bb_root = Path(bb_root)
        self._agent_id = agent_id
        self._state_path = self._bb_root / "agents" / f"{agent_id}.state.json"

    @property
    def state_path(self) -> Path:
        return self._state_path

    def load(self) -> WorkerState:
        """加载状态。文件不存在或损坏时返回默认空状态。"""
        if not self._state_path.exists():
            return WorkerState()
        try:
            content = self._state_path.read_text(encoding="utf-8")
            if not content.strip():
                return WorkerState()
            data = json.loads(content)
            return WorkerState.from_dict(data)
        except (json.JSONDecodeError, ValueError, TypeError) as e:
            logger.warning(
                "Worker %s state.json 解析失败，使用默认空状态: %s (path=%s)",
                self._agent_id, e, self._state_path,
            )
            return WorkerState()

    def save(self, state: WorkerState) -> None:
        """原子写入状态。"""
        state.last_updated_at = _now_iso()
        try:
            validate_path_safety(self._bb_root, self._state_path)
        except PathSafetyError as e:
            raise WorkerStateError(f"state path safety violation: {e}") from e

        content = json.dumps(state.to_dict(), ensure_ascii=False, indent=2)
        try:
            atomic_write(self._state_path, content)
        except Exception as e:
            raise WorkerStateError(f"failed to write state: {e}") from e

    def update(self, updates: dict[str, Any]) -> WorkerState:
        """读取 → 合并 → 写入（事务性）。

        Args:
            updates: 字段名到新值的映射。set 类型字段会合并而非替换。
                     如 {"responded_request_seqs": {1, 2}} 会追加 1, 2 到现有集合。

        Returns:
            合并后的新状态
        """
        current = self.load()
        set_fields = {
            "responded_request_seqs",
            "processed_msg_seqs",
            "processed_urgent_seqs",
            "executed_op_ids",
        }
        for key, value in updates.items():
            if key in set_fields:
                getattr(current, key).update(value)
            elif hasattr(current, key):
                setattr(current, key, value)
        self.save(current)
        return current
```

```python
def _make_worker(bb_root, agent_id="agent_A", orchestrator=None):
    config = {
        "multiagent": {
            "worker": {"capabilities": ["sentiment_analysis"]},
            "director": {},
            "collab": {"poll_interval_seconds": 2, "idle_timeout_seconds": 60},
        }
    }
    return WorkerAdapter(
        bb_root=bb_root, config=config, agent_id=agent_id,
        orchestrator=orchestrator or AsyncMock(),

def test_worker_loads_last_collab_seq_from_state_on_start(bb_root):
    """启动时从 state 文件恢复 _last_collab_seq，跳过历史消息。"""
    # 1. 预先写入 state 文件，记录 last_collab_seq=5
    store = WorkerStateStore(bb_root, "agent_A")
    store.save(WorkerState(last_collab_seq=5))

    # 2. 在 collaboration.md 写入 seq=1..3 的历史消息
    for i in range(1, 4):
        asyncio.run(append_collab_message(bb_root, {
            "from": "agent_B", "type": "relay", "content": f"历史消息 {i}",
        }))

    asyncio.run(worker._load_state_on_start())

    assert worker._last_collab_seq == 5

    # 5. 验证：轮询一次后不会处理 seq<=5 的历史消息
    asyncio.run(worker._poll_collab_once())
    assert len(worker._normal_queue) == 0  # 历史消息被跳过
```

```python
        """轮询一次协作消息（增量 seq 处理 + 批量持久化 last_collab_seq）。

        深度 Review 修正：原实现每条消息处理后立即推进 _last_collab_seq 但不持久化，

            m for m in messages
            if isinstance(m.get("seq"), int) and m["seq"] > self._last_collab_seq
        ]

        if not new_messages:
            return

        max_seq = self._last_collab_seq
        for msg in new_messages:

            seq = msg.get("seq", 0)
            if isinstance(seq, int) and seq > max_seq:
                max_seq = seq

        # 批量推进 _last_collab_seq
        if max_seq > self._last_collab_seq:
            self._last_collab_seq = max_seq
            # 持久化 last_collab_seq（防止崩溃丢失）
            await self._persist_last_collab_seq()
```

```python
# teage_liu/multiagent/worker_adapter.py 替换 _rebuild_state_from_history 方法
    async def _rebuild_state_from_history(self):
        """扫描 collaboration.md + messages.md 历史构建初始 state。

        仅在 state.json 不存在时调用（首次升级或新 agent）。

        【深度 Review 修正】设计原则：
        - last_collab_seq 保持为 0：让轮询重新处理历史消息，由幂等集防止重复副作用。
          如果设为最大 seq，会跳过未处理的用户广播（测试 test_rebuild_allows_unhandled_broadcast_to_be_processed）。
        - processed_msg_seqs / processed_urgent_seqs 保持为空：无法准确判断哪些消息已处理，
          留空更安全（最坏情况是重复入队或重复触发 LLM 一次，但不会跳过未处理消息）。
        - 只初始化可准确判断的幂等集：
          * responded_request_seqs：基于已写过的 type=response 消息的 reply_to 字段
          * executed_op_ids：基于已写过的 type=result 消息的 task_op_id 字段
        """
        from teage_liu.multiagent.blackboard import (
            read_collab_messages, read_messages,
        )
        from teage_liu.multiagent.worker_state import WorkerState

        state = WorkerState()  # last_collab_seq=0, 所有集合为空

        # 1. 扫描 collaboration.md
        try:
            collab_msgs = await read_collab_messages(self._bb_root)
        except Exception as e:
            logger.warning(
                "Worker %s 扫描 collaboration.md 失败: %s",
                self._agent_id, e,
            )
            collab_msgs = []

        for msg in collab_msgs:
            # 已写过的 response → 把 reply_to 加入 responded_request_seqs
            if (msg.get("type") == "response"
                    and msg.get("from") == self._agent_id
                    and isinstance(msg.get("reply_to"), int)):
                state.responded_request_seqs.add(msg["reply_to"])

        # 2. 扫描 messages.md（A2A 任务结果）
        try:
            task_msgs = await read_messages(self._bb_root)
        except Exception as e:
            logger.warning(
                "Worker %s 扫描 messages.md 失败: %s",
                self._agent_id, e,
            )
            task_msgs = []

        for msg in task_msgs:
            # 自己写过的 result → 把 task_op_id 加入 executed_op_ids
            if (msg.get("type") == "result"
                    and msg.get("from") == self._agent_id
                    and msg.get("task_op_id")):
                state.executed_op_ids.add(msg["task_op_id"])

        # 3. 持久化（避免下次启动再扫描）
        if self._persist_state:
            try:
                self._state_store.save(state)
                logger.info(
                    "Worker %s 历史扫描完成并持久化：collab_msgs=%d, responded=%d, executed=%d",
                    self._agent_id, len(collab_msgs),
                    len(state.responded_request_seqs),
                    len(state.executed_op_ids),
                )
            except Exception as e:
                logger.warning(
                    "Worker %s 历史扫描后持久化失败（不阻塞启动）: %s",
                    self._agent_id, e,
                )

        return state
```

```python
    async def _handle_request(self, msg: dict) -> None:
        """处理协作请求（区分用户广播紧急 / 普通请求入队）。

        幂等性检查（防止重启后重复响应/重复入队）：
        - 【深度 Review 修正】只检查 _responded_request_seqs（已响应过的 request 跳过）
        - 普通_request 入队后立即标记为 processed（防止重启后重复入队）
        - 用户广播由 _trigger_urgent_llm 成功后标记到 _responded_request_seqs（Task 5）

        注：不检查 _processed_msg_seqs 作为 request 的兜底，因为：
        1. Task 3 的 _rebuild_state_from_history 不初始化 _processed_msg_seqs
        2. Task 5 异常路径不更新 _processed_msg_seqs，允许 LLM 失败后重试
        3. _processed_msg_seqs 仅用于普通队列消息（relay/response/result/ordering directive）去重
        """
        # 检查是否需要自己的能力
        capabilities_needed = msg.get("capabilities_needed", [])
        if capabilities_needed:
            my_caps = self._config.get("capabilities", [])
            if not any(cap in my_caps for cap in capabilities_needed):
                return  # 能力不匹配，跳过

        # 检查 target
        target = msg.get("target_agents", [])
        if target and self._agent_id not in target and "*" not in target:
            return  # 不是发给自己的

        msg_seq = msg.get("seq")

        # 判断是否用户广播（紧急插队）
        if msg.get("from") == "user":

                logger.debug(
                    "Worker %s 跳过已响应的用户广播 seq=%d",
                    self._agent_id, msg_seq,
                )
                return
            await self._trigger_urgent_llm(
                prompt=f"用户广播协作请求：{msg.get('content', '')}\n请决定是否参与并回复。",
                context_msg=msg,
            )
        else:
            # 普通请求：检查 _processed_msg_seqs 防止重复入队
            if isinstance(msg_seq, int) and msg_seq in self._processed_msg_seqs:
                logger.debug(
                    "Worker %s 跳过已入队的普通 request seq=%d",
                    self._agent_id, msg_seq,
                )
                return
            # 普通：进入队列，等 A2A 主泵触发
            self._normal_queue.append(msg)
            # 立即标记为已处理（防止重启后重复入队）
            await self._mark_msg_processed(msg_seq)
```

```python
# teage_liu/multiagent/worker_adapter.py 替换 _trigger_urgent_llm 方法（601-640 行）
    async def _trigger_urgent_llm(self, prompt: str, context_msg: dict) -> None:
        """紧急插队：立即触发 LLM 调用（不搭便车，但顺便清空普通队列）。

        【深度 Review 修正】副作用完成后更新幂等集 + 持久化：
        - 成功路径：根据消息类型更新 _responded_request_seqs / _processed_urgent_seqs
        - 异常路径：不更新任何幂等集，允许重试（防止 LLM 临时故障导致永久跳过）
        """
        if self._orchestrator is None:
            return
        system_prompt = self._build_urgent_system_prompt(context_msg)
        # 同时把普通队列消息也注入（顺便清空）
        system_prompt = self._inject_normal_queue_to_context(system_prompt)

        # 协作专用 session（与用户主对话隔离）
        collab_session_id = f"multiagent_{self._agent_id}"
        msg_seq = context_msg.get("seq")
        msg_type = context_msg.get("type")
        rule_type = context_msg.get("rule_type", "")

        try:
            response = await self._orchestrator.chat(
                collab_session_id, prompt,
                extra_system_prompt=system_prompt,
            )
        except Exception as e:
            logger.exception("Worker %s 紧急 LLM 调用失败: %s", self._agent_id, e)
            # 异常时写 error 消息告知用户，不静默丢弃
            from teage_liu.multiagent.blackboard import append_collab_message
            await append_collab_message(self._bb_root, {
                "from": self._agent_id,
                "type": "response",
                "reply_to": msg_seq,
                "content": f"[协作响应失败] {type(e).__name__}: {e}",
                "accept": False,
                "error": True,
            })
            # 【深度 Review 修正】异常路径不更新幂等集，允许重试
            return
        self._last_a2a_time = time.time()

        # 如果是 request，写 response
        if msg_type == "request":
            from teage_liu.multiagent.blackboard import append_collab_message
            await append_collab_message(self._bb_root, {
                "from": self._agent_id,
                "type": "response",
                "reply_to": msg_seq,
                "content": str(response),
                "accept": True,
            })
            # 成功响应：加入 _responded_request_seqs
            await self._mark_request_responded(msg_seq)

        # intervention directive：加入 _processed_urgent_seqs
        if msg_type == "directive" and rule_type == "intervention":
            await self._mark_urgent_processed(msg_seq)

    async def _mark_request_responded(self, msg_seq: int | None) -> None:
        """标记 request 已响应，更新内存集合 + 持久化。"""
        if not isinstance(msg_seq, int):
            return
        self._responded_request_seqs.add(msg_seq)
        if not self._persist_state:
            return
        try:
            self._state_store.update({"responded_request_seqs": {msg_seq}})
        except Exception as e:
            logger.warning(
                "Worker %s 持久化 responded_request_seqs=%d 失败: %s",
                self._agent_id, msg_seq, e,
            )

    async def _mark_urgent_processed(self, msg_seq: int | None) -> None:
        """标记 intervention directive 已处理，更新内存集合 + 持久化。"""
        if not isinstance(msg_seq, int):
            return
        self._processed_urgent_seqs.add(msg_seq)
        if not self._persist_state:
            return
        try:
            self._state_store.update({"processed_urgent_seqs": {msg_seq}})
        except Exception as e:
            logger.warning(
                "Worker %s 持久化 processed_urgent_seqs=%d 失败: %s",
                self._agent_id, msg_seq, e,
            )

    async def _mark_msg_processed(self, msg_seq: int | None) -> None:
        """标记消息已处理（普通队列去重），更新内存集合 + 持久化。"""
        if not isinstance(msg_seq, int):
            return
        self._processed_msg_seqs.add(msg_seq)
        if not self._persist_state:
            return
        try:
            self._state_store.update({"processed_msg_seqs": {msg_seq}})
        except Exception as e:
            logger.warning(
                "Worker %s 持久化 processed_msg_seqs=%d 失败: %s",
                self._agent_id, msg_seq, e,
            )
```

```python
    async def _handle_directive(self, msg: dict) -> None:
        """处理 Director directive（按 rule_type 分类：intervention 紧急 / 其他入队）。

        幂等性检查：
        - intervention：检查 seq in _processed_urgent_seqs，已处理则跳过
        - ordering/constraint：检查 seq in _processed_msg_seqs，已处理则不重复入队；
          入队后立即标记为 processed（防止重启后重复入队）
        """
        target = msg.get("target", "*")
        if target != "*" and target != self._agent_id:
            return  # 不是给自己的

        msg_seq = msg.get("seq")
        rule_type = msg.get("rule_type", "")

        if rule_type == "intervention":
            # 幂等检查：已处理过的 intervention 跳过
            if isinstance(msg_seq, int) and msg_seq in self._processed_urgent_seqs:
                logger.debug(
                    "Worker %s 跳过已处理的 intervention directive seq=%d",
                    self._agent_id, msg_seq,
                )
                return
            # 紧急：立即触发 LLM（紧急插队）
            await self._trigger_urgent_llm(
                prompt=f"Director 应急干预：{msg.get('content', '')}\n请立即响应。",
                context_msg=msg,
            )
        else:
            # 幂等检查：已处理过的 ordering/constraint 不重复入队
            if isinstance(msg_seq, int) and msg_seq in self._processed_msg_seqs:
                logger.debug(
                    "Worker %s 跳过已处理的 %s directive seq=%d",
                    self._agent_id, rule_type, msg_seq,
                )
                return

            self._normal_queue.append(msg)
            # 立即标记为已处理（防止重启后重复入队）
            await self._mark_msg_processed(msg_seq)
```

```python
    async def _handle_collab_message(self, msg: dict) -> None:
        """处理单条协作消息（按消息类型路由）。

        幂等性策略：
        - request / intervention directive：由各自 handler 内部精确检查
          （_responded_request_seqs / _processed_urgent_seqs），不在此处兜底
        - relay / response / result / ordering directive：检查 _processed_msg_seqs，
          已处理则跳过；处理（入队）后立即标记为已处理
        """
        msg_type = msg.get("type")
        msg_seq = msg.get("seq")

        if msg_type == "directive":
            await self._handle_directive(msg)
        elif msg_type == "request":
            await self._handle_request(msg)
        elif msg_type == "announce":
            # 其他 agent 的 announce，仅记录，不触发 LLM
            pass
        elif msg_type == "relay":
            # 幂等检查：已处理过的 relay 不重复入队
            if isinstance(msg_seq, int) and msg_seq in self._processed_msg_seqs:
                return
            # relay 消息已在 A2A 中处理，记录上下文（普通队列）
            self._normal_queue.append(msg)
            # 立即标记为已处理（防止重启后重复入队）
            await self._mark_msg_processed(msg_seq)
        elif msg_type == "status":
            # 状态更新，不触发 LLM，不入队
            pass
        elif msg_type in ("response", "result"):
            # 幂等检查：已处理过的不重复入队
            if isinstance(msg_seq, int) and msg_seq in self._processed_msg_seqs:
                return
            # response/result 进入普通队列，搭便车
            self._normal_queue.append(msg)
            # 立即标记为已处理
            await self._mark_msg_processed(msg_seq)
```

```python
    async def execute_a2a_task(
        self, task_op_id: str, task_content: str,
        extra_context: str = "",
    ) -> dict:
        """执行 A2A 任务（幂等入口）。

        幂等性：task_op_id 在 _executed_op_ids 中则直接返回 cached=True，不重复执行。

        Args:
            task_op_id: 任务操作 ID（幂等键）
            task_content: 任务内容
            extra_context: 额外上下文（如 Director 引导）

        Returns:
            {"cached": bool, "result": str, "op_id": str}
        """
        # 幂等检查
        if task_op_id in self._executed_op_ids:
            logger.info(
                "Worker %s 跳过已执行的 A2A 任务 op_id=%s",
                self._agent_id, task_op_id,
            )
            return {"cached": True, "result": "", "op_id": task_op_id}

        # 执行任务（调用 LLM）
        if self._orchestrator is None:
            return {"cached": False, "result": "", "op_id": task_op_id, "error": "no orchestrator"}

        collab_session_id = f"multiagent_{self._agent_id}"
        prompt = f"A2A 任务：{task_content}"
        system_prompt = "你是协作 agent，负责执行 A2A 任务。"
        if extra_context:
            system_prompt += f"\n\n{extra_context}"

        try:
            response = await self._orchestrator.chat(
                collab_session_id, prompt,
                extra_system_prompt=system_prompt,
            )
        except Exception as e:
            logger.exception(
                "Worker %s A2A 任务执行失败 op_id=%s: %s",
                self._agent_id, task_op_id, e,
            )
            # 写 error result 消息
            from teage_liu.multiagent.blackboard import append_message
            await append_message(self._bb_root, {
                "from": self._agent_id,
                "type": "result",
                "task_op_id": task_op_id,
                "content": f"[任务执行失败] {type(e).__name__}: {e}",
                "accept": False,
                "error": True,
            })
            # 失败也标记为已执行（避免无限重试）
            self._executed_op_ids.add(task_op_id)
            try:
                self._state_store.update({"executed_op_ids": {task_op_id}})
            except Exception as persist_err:
                logger.warning("持久化 executed_op_ids 失败: %s", persist_err)
            return {
                "cached": False, "op_id": task_op_id,
                "error": str(e), "result": "",
            }

        self._last_a2a_time = time.time()

        # 写 result 消息
        from teage_liu.multiagent.blackboard import append_message
        await append_message(self._bb_root, {
            "from": self._agent_id,
            "type": "result",
            "task_op_id": task_op_id,
            "content": str(response),
            "accept": True,
        })

        # 标记为已执行
        self._executed_op_ids.add(task_op_id)
        try:
            self._state_store.update({"executed_op_ids": {task_op_id}})
        except Exception as persist_err:
            logger.warning("持久化 executed_op_ids 失败: %s", persist_err)

        return {
            "cached": False, "result": str(response), "op_id": task_op_id,
        }
```

```python
    # （error response 是 LLM 失败时写的，对应 request 不应被标记为已响应）
    if (msg.get("type") == "response"
            and msg.get("from") == self._agent_id
            and isinstance(msg.get("reply_to"), int)
            and msg.get("accept") is True):
        state.responded_request_seqs.add(msg["reply_to"])
```

### 关键问题 B（设计矛盾）：`_trigger_urgent_llm` 异常"允许重试" vs `_poll_collab_once` 推进 `_last_collab_seq` 导致无法重试

**问题**：
- Task 5 修正说"异常路径不更新幂等集，允许重试"
- 但 Task 2 的 `_poll_collab_once` 批量推进 `_last_collab_seq` 并持久化（无论 LLM 是否成功）
- 重启后 `_last_collab_seq` 已推进到该消息 seq，`_poll_collab_once` 过滤 `seq > _last_collab_seq`，**不会重新读取该消息**
- 后果：LLM 失败后，该 request 实际上**无法被重试**（与设计意图矛盾）

**当前行为分析**：
- 单次进程内：LLM 失败后，`_last_collab_seq` 已推进，本轮不会重新处理。但消息在内存中（如果入队的话）可能被重试。然而用户广播走 `_trigger_urgent_llm` 不入队，所以单次进程内也无法重试。
- 跨重启：state.json 中 `_last_collab_seq` 已推进，重启后不会重新读取该消息。

**修正方案**（取舍）：
- **方案 1（推荐，最小改动）**：保留当前行为，但在文档中明确说明"LLM 失败后该 request 不会被自动重试，需用户重新发送广播或后续实现重试机制"
- 方案 2：`_trigger_urgent_llm` 异常时把消息加入 `_urgent_queue` 或 `_retry_queue`，由空闲检查或下次轮询重试（需新增重试逻辑，超出当前修复范围）
- 方案 3：`_poll_collab_once` 中 LLM 失败时不推进 `_last_collab_seq`（破坏批量推进逻辑，且会导致其他消息被阻塞）

**采用方案 1**：在 Task 11 的 docstring 中明确说明此限制，并在 Task 5 的 `_trigger_urgent_llm` 异常路径注释中修正措辞（从"允许重试"改为"不更新幂等集，但 `_last_collab_seq` 已推进，实际不会自动重试，需用户重新发送"）。

**影响位置**：
- `worker_adapter.py:933`（`_trigger_urgent_llm` 异常路径注释）
- Task 11 的 docstring

### 关键问题 C（设计不一致）：`execute_a2a_task` 失败也标记为已执行 vs `_trigger_urgent_llm` 异常不更新幂等集

**问题**：
- Task 8 的 `execute_a2a_task` 异常路径：`self._executed_op_ids.add(task_op_id)` + 持久化（"避免无限重试"）
- Task 5 的 `_trigger_urgent_llm` 异常路径：不更新任何幂等集（"允许重试"）
- 两个方法的失败处理策略**不一致**

**合理性分析**：
- `execute_a2a_task` 是显式调用（由 A2A Gateway 或调度器调用），调用方可根据返回的 `error` 字段决定是否重试。方法内"失败也标记"是避免调用方无限重试，由调用方决策。
- `_trigger_urgent_llm` 是内部触发（由轮询驱动），无外部调用方决策。但实际上由于关键问题 B，也无法重试。

**结论**：两个方法的失败处理策略不同是合理的，但需要在文档中明确说明差异。

**修正**：在 Task 8 的 `execute_a2a_task` docstring 中说明"失败也标记为已执行，避免调用方无限重试；调用方可根据返回的 error 字段决策"。

**影响位置**：Task 8 的 `execute_a2a_task` docstring
