# 新系统重构 — 主干-枝干架构设计

> 配套文档：[docs/SUBSYSTEM-SPI.md](../../docs/SUBSYSTEM-SPI.md)(子系统接入契约)、[docs/ARCHITECTURE.md](../../docs/ARCHITECTURE.md)(现状)、[docs/ISSUES-2026-08-11-架构问题清单.md](../../docs/ISSUES-2026-08-11-架构问题清单.md)(现状问题依据)
> 状态：设计定案(待 D-OPEN-1 闭环),开工后本文件作为 `teage_liu2/` 的架构依据

## 1. 背景与动机

现状代码(约 6.4 万行)经过近两个月演进,已具备较完整的对话/记忆/工具/多智能体能力,但存在三类结构性问题(详见问题清单):

1. **装配双轨制**:`set_instance` 绕过工厂注入 + `app.state.*` 兼容层,组件创建路径不唯一;
2. **静默吞错**:14+29 处裸 `except Exception` 使组件故障无感知,可拔性由"故障驱动"意外长出;
3. **巨型类**:worker_adapter.py 3280 行等,单一职责失效。

同时,项目已确立新的**设计理念**(见 §2):以"用户与 LLM 直接对话"为主干,其余子系统全部为可插拔枝干。现有代码已 80% 具备"判空+降级"的退化接入能力,但它是**意外长出来的**,不是**声明出来的**——需要一次显式化重构,将"故障驱动的可拔"转为"配置驱动的可插拔"。

## 2. 核心设计理念(项目长期方向)

```
主干(Core)= 不可再减的对话动作 + 扩展机制
  输入 → [钩子链 before] → LLM 调用 → [钩子链 after] → 输出

枝干(Branch)= 实现 Branch 接口的子系统,互不可见,可拔插
  react 循环 / 记忆 / 护栏 / 工具 / 意图 / 调度 / 协作……
```

- **无子系统照样能运行**:最小实现 = 主干 + 零枝干;
- **"第 N+1 个枝干出现时,主干零改动"** —— 这是新骨架的验收底线;
- 现状"判空+降级"是雏形,目标"配置开关 + 钩子注册"是显式形态(见 SUBSYSTEM-SPI.md §8 迁移路径)。

## 4. 目标分层与依赖铁律

```
┌─ 外壳 server/(可替换):FastAPI / CLI / Tauri ────────────────┐
│   传输层:SSE(事件流编码器)/ REST —— 只依赖主干,不感知枝干   │
├─ 主干 core/(固定,零枝干可跑)───────────────────────────────┤
│   pipeline(装配:裸形态/循环形态)                            │
│   step(单次 LLM 调用 → 事件流)/ loop(循环形态,搬老 ReactLoop)│
│   hooks(HookChain:BranchContext / Branch 基类)              │
│   llm(多 provider 抽象)/ history(HistoryStore SPI)          │
│   config / types(消息模型 + 事件类型)                       │
├─ 枝干 branches/(可插拔,互不可见,只依赖 core)───────────────┤
│   guardrails / tools / memory / intent / skill /            │
│   mcp / scheduler / multiagent                              │
└──────────────────────────────────────────────────────────────┘
```

**依赖铁律**(违反即 PR 打回):
1. 主干不知道任何枝干的名字;
2. 枝干依赖 core 的接口,不依赖彼此(枝干间只经 `BranchContext.extra` 通信);
3. 外壳只依赖主干(不感知 branches)。

## 6. 事件流类型草案(core/types.py,基建)

```python
# 事件:主干产出的最小单元,外壳编码为 SSE,非流式收集拼字符串
Event = {
    "type": "text_delta" | "text_done" | "tool_use" | "tool_result"
          | "step_start" | "step_end" | "done" | "error",
    "session_id": str, "payload": dict,
}
```

- pipeline 为 `async generator: (session_id, user_input) → AsyncIterator[Event]`;
- 非流式 = 收集 `text_delta` 拼字符串(5 行薄壳);
- SSE = Event → `data:` 帧(外壳侧,后置)。

## 7. 循环形态设计(核心新形态)

```
裸形态:   [step: LLM 调用] ──事件──▶ done

循环形态: [step: LLM 调用] ──事件──▶ tool_use?
              ▲                        │
              │                    HookChain.on_tool_call(遍历枝干,首个非 NotImplemented 者执行)
              │                        │
              └──── end_turn / max_loops / 无执行者 ── 回喂 tool_result ──┘
```

- 循环形态**不引用任何工具枝干**,只通过 HookChain 触发 `on_tool_call`;工具枝干不存在(全 NotImplemented)→ 友好终止("LLM 想调工具但无人执行");
- 无工具时自动单轮 = 裸形态,与现状 `react_loop.py:92` "tool_registry=None → 纯对话模式"行为一致;
- 事件流天然支持多步:每步 = 事件流中的一段(step_start/step_end)。
