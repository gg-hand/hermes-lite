## 1. P1 缺陷(2 个,已实测确认)

### Q1 — 多轮工具场景 done.response 被全轮拼接覆盖,拼接文本落盘污染历史
- **位置**:`teage_liu2/core/pipeline.py:142-151`(text_parts 累积全部轮次 text_delta;done 处 `ev["response"] = "".join(text_parts)` 覆盖 loop 值并落盘)与 `teage_liu2/core/loop.py:131-133`(last_text 每轮覆盖,只保留最后轮文本)
- **现象**:两轮场景(第一轮"我需要查一下"+tool_use → 第二轮"查到了:晴天")→ `done.response = '我需要查一下查到了:晴天'`;落盘 assistant 内容 = 该拼接串(一条从未真实存在的合并消息),持久污染 SQLite 权威库,重启后 LLM 历史与现场结构不一致,破坏计划 §1.3"重启重建配对结构"的基础
- **根因**:同一字段两处计算语义冲突——loop 的 last_text 是"最后轮"语义,pipeline 覆盖为"全轮拼接"语义;test_loop.py:42-52 工具脚本第一轮恰好只有 tool_use 无文本,test_persist 6 例全部单轮,测试盲区未被锚定
- **修复方向**:loop 模式优先采用 done 事件原始 response(或从 done.messages[-1] 提取收尾文本);pipeline 仅在无 response 时兜底;落盘与真实 assistant 消息一一对应,与计划 §1.3 step_end 逐条落盘衔接

### N1 — on_tool_call 异常穿透事件流,违反计划 §4.4 错误责任矩阵(plan-auditor 独立发现)
- **位置**:`teage_liu2/core/loop.py:166`(await dispatch_tool_call)与 `teage_liu2/core/hooks.py:194-196`(裸 await,无 try/except)
- **现象**:工具枝干 raise → 异常穿透 run_stream → chat_stream 直接抛,事件流无 error 事件、无 tool_result is_error 回喂,落盘仅 user;SSE 客户端收到 500 中断。计划 §4.4 明确"工具执行失败 → 枝干自身 → tool_result is_error → loop 回喂 LLM";SPI §3"单枝干故障不影响对话"被违反
- **修复方向**:dispatch_tool_call 内捕获异常返回 Exception 实例——loop.py:186-190 已有 `is_error = isinstance(result, Exception)` 通道,仅 dispatch 层未接上
