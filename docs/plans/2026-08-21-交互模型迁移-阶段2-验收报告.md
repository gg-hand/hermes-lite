## 三、执行中的关键决策

1. **推翻 BranchContext → Snapshot + Action**（§17 定案）：`BranchContext` 删除；`Branch` 11 钩子全部新签名（`before(snapshot) -> Action[]`、`inject_round -> Injection`、`setup(config, host)`、新增 pre/post_tool_call/after_step）。既有 6 个测试文件适配新签名（hooks/loop/pipeline/persist/injection/registry），85 测试全绿。
2. **非法消息序列语义变更**：原测试"before 直接 append 连续 user → error 事件"在新架构下不成立——§4.4 规定 append 仅允许 role=user，且 merge 相邻 user 由收口统一执行（扩展无法绕过交替校验）。测试改为"AppendMessage 追加 assistant 被 schema 拒绝（HOOK_INVALID_ACTION），对话正常继续"（§15-A1 边界校验锚定）。
3. **stop_reason 实现层字段**：`Snapshot` 增加 `stop_reason`（frozen dataclass 内部字段），`to_dict` 不导出（保持协议 11 键）；SetStop action 的 reason 经此呈现为 done(intercepted)。
4. **资源上限**：`RESOURCE_LIMITS` 协议常量实施（消息条数/单条体积 append 前拒绝 + 快照总体积 error 记录）；`CoreConfig` 新增三个独立配置项（默认 = 协议常量），`config.schema.json` CoreConfig 同步补字段（唯一契约源一致，check_schema 通过）。
5. **L3 仅 schema 对拍**（§18.5）：`event_stream.py` 定义 L1/L3/外壳直通分类 + L3 拦截点（route_l3），批处理/有界队列随阶段 3 transport 落地——不抢跑。
6. **observe 只读强制**（§15-A4③）：observe 扩展钩子返回 action → 忽略 + error 级日志，不推进快照、不短路。
