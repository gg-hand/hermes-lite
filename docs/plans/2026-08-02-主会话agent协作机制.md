## 1. 背景与动机

主会话（用户聊天 session，`POST /chat` 与 `/chat/stream`）目前**无法自主调用其他 agent 协作**。经调查确认存在五条断链：

| # | 断链 | 位置 |
|---|------|------|
| 1 | 工具不注册 | 跨 agent 工具被 `a2a.enabled` 门控（[lifespan.py:496](teage_liu/lifespan.py#L496)），默认 `config.yaml` 无 `a2a` 段 |
| 2 | prompt 无引导 | 主 `SYSTEM_PROMPT`（[prompts.py:8](teage_liu/llm/prompts.py#L8)）无任何协作/委托指引；协作 prompt 只注入 worker 协作会话 |
| 3 | 无 collab_id 上下文 | `_current_collab_id` contextvar 只在 worker 路径 set（[worker_adapter.py:2103](teage_liu/multiagent/worker_adapter.py#L2103)），主会话为 None → `wait_for_response` 静默失效 |
| 4 | 对端不即时触发 | agent-to-agent request 只入普通队列搭便车（[worker_adapter.py:1790](teage_liu/multiagent/worker_adapter.py#L1790)） |
| 5 | 线程阻塞 | 工具在事件循环线程同步执行（[tool_registry.py:322](teage_liu/agent/tool_registry.py#L322)），阻塞会冻结服务 |

设计意图见 [collab-fix-plan.md](docs/plans/collab-fix-plan.md) 决策9（"主会话发起协作用 subagent 阻塞模式"）与决策7（"`initiate_collaboration` 工具全局注册"，未落地）。

本规范确立主会话协作的 **v2 双平面架构**：主会话协作走**独立 A2A 端到端通道**，与 worker 协作平面彻底分离。

## 2. 现状与断链分析

（见第 1 节表格 + 工作台/前端现状：）

- 前端 `chat-collab-bridge.js` 已支持把 `type=request&&from==local` 注入 `collab_progress`、`type=response&&to==local` 注入 `collab_result` 到主对话——主会话协作的展示通道已存在。
- 工作台 `collab-workbench.js` 读取 `collaboration.md` + `collabs/*.md`（SSE），现有广播/引导写控件。
- `send_remote_message`/`list_remote_agents`（[a2a_tools.py](teage_liu/agent/tools/a2a_tools.py)）已实现 本地写入 + A2A 转发 + `wait_for_response` 轮询，可复用内部机制。

## 3. 总体设计（双平面架构）

```
┌─ 主会话协作平面（新，A2A e2e）────────────────────────────────┐
│  用户 ←主对话→ 主会话agent(teagent-lu) ──request_collaboration──▶
│        A2A call_all_endpoints("collab_message", {channel:main_session})
│        对端网关 → 按 to==self 过滤 → 写本地 collabs/main_{cid}.md（镜像）
│        → 对端 main-collab handler → 独立上下文触发 LLM 响应
│        → A2A 回传 → 发起方镜像 → wait_for_response 轮询本地
│        → 工具写 type=end → 双方镜像 → 归档
│  工作台（每端）：SSE 聚合 main_* 消息，纯观察 + 独立标识 + 归档
└───────────────────────────────────────────────────────────────────┘
┌─ worker 协作平面（现有，共享黑板）─────────────────────────────┐
│  worker 自主协商：collaboration.md + collabs/collab_*.md        │
│  WorkerAdapter 轮询 → _handle_collab_message（首行过滤 channel= │
│  main_session，只处理 worker 消息）；工作台可广播/注入引导        │
└───────────────────────────────────────────────────────────────────┘
```

### 时序（A2A e2e，方案Y 独立黑板 / 方案X 共享黑板均适用）

```
主会话 LLM ── request_collaboration(teagent-liu-2, task, timeout)
  ① 生成 collab_id=main_{uuid} + message_id
  ② 构造 {channel:main_session, type:request, from:teagent-lu, to:teagent-liu-2,
          content, collab_id, message_id, priority:high, wait_for_response, deadline, collab_round:1}
  ③ 本地镜像请求 → collabs/main_{cid}.md（SSE→工作台/主对话进度）
  ④ call_all_endpoints("collab_message", params) 广播
  ⑤ asyncio.to_thread 内 _wait_for_response 轮询本地镜像
     （匹配 to==self && type∈{response,consensus,end} && seq>sent，0.5s，检查 cancel）
  ⑥ 摘要截断(max_result_chars) 返回主会话 LLM；写 type=end 归档

对端 teagent-liu-2：
  网关 collab_message：to==self → 写本地镜像 main_{cid}
  → worker 轮询读 main_* → _handle_main_collab_message（channel 分流）
  → request 且 from≠self → _trigger_main_collab_llm（独立上下文）
  → LLM 回复 → 写 response(channel, to=teagent-lu) → call_all_endpoints 回传
  → 发起方网关按 collab_id 存在性过滤 → 写本地镜像 → 发起方 wait 命中
```

## 4. 设计规范（协议与约定）

### 4.1 命名规范
- `channel` 枚举：`"main_session"`（主会话协作平面）/ 缺省或 `"worker"`（worker 协作平面）。互斥，消息必含其一。
- `collab_id` 前缀：主会话协作 `main_`（`main_{uuid4().hex[:12]}`）；worker 协作 `collab_`（现有）。
- A2A 方法：新增 `collab_message`（主会话协作平面专用）；`agent_message`/`director_broadcast` 保持 worker 平面语义。
- 主会话工具：`list_collab_agents` / `request_collaboration`（peer-collab 语义，不出现 worker 术语如 collab_id/msg_type/round）。

### 4.2 消息协议规范
- 请求：`{channel:"main_session", type:"request", from, to, content, collab_id, message_id, priority:"high", wait_for_response, deadline, collab_round:1}`。
- 响应：`{channel:"main_session", type:"response", from, to:<发起方>, content, collab_id, message_id, collab_round}`。
- 归档：`{channel:"main_session", type:"end", from, to, collab_id, message_id}`（完成标记，触发归档）。
- **路由**：request 按 `to` 字段分发（`to==self || to=="*"` 命中）；response/end 按 `collab_id` 是否在本地 index 存在分发（非参与者丢弃，防广播污染）。
- **幂等**：`message_id` 跨端一致为幂等键；`_dk(collab_id, seq, message_id)` 复用现有机制（[worker_adapter.py:714](teage_liu/multiagent/worker_adapter.py#L714)）。
- **镜像**：每端对参与协作的每条消息 append 写本地 `collabs/main_{cid}.md`（不覆盖，两端独立 seq）。

### 4.3 工作台展示规范
- `channel=="main_session"` 消息带"主会话协作"徽章 / 独立 CSS 分组。
- main_* 协作对工作台**只读**（broadcast/directive/append 写控件隐藏或禁用；后端拒绝）。
- 归档后进入"已归档"分组，标识保留。

### 4.4 安全规范
- A2A `collab_message` 字段**白名单透传**（不透传任意 params）；collab_id `sanitize_path` 防穿越；统一 rate limit。
- 非参与者丢弃（防广播污染）；`to` 过滤防误触发。
- 会话级工具隔离：主会话/worker 协作会话工具集互不可见（`tools_override` + contextvar 兜底）。

## 5. 协议定义

- 消息字段扩展：新增 `channel`（见 4.1）。
- `collab_message` JSON-RPC 方法：接收方网关白名单透传字段 → `sanitize_path` 校验 collab_id → 按 `to` / index 存在性过滤 → 写本地 `collabs/main_{cid}.md` → 返回 `{ok, seq}` ack。
- `read_collab_messages(collab_id, after_seq)` 复用现有 blackboard 能力（[blackboard.py:547](teage_liu/multiagent/blackboard.py#L547)）。

## 6. 配置项

```yaml
multiagent:
  main_session_collab:
    enabled: true          # 总开关（false=零注册零注入零影响）
    inject_prompt: true    # 注入协作引导段（extra_system_prompt）
    register_tools: true   # 注册 list_collab_agents / request_collaboration
    default_timeout: 60    # 阻塞等待默认秒数
    max_timeout: 300       # 上限（工具层二次钳制）
    max_result_chars: 4000 # 响应摘要上限（防上下文膨胀）
    mode: peer             # 预留: peer(当前) | subagent(未来)
    discovery:
      local: true          # AgentRegistry 本地发现
      a2a: true            # A2A list_agents（需 a2a.enabled）
```

## 7. 工具定义

### 7.1 `list_collab_agents`
- 作用：发现在线可协作的平级 agent（A2A `list_agents` + 本地 `AgentRegistry`，排除 self），返回 `{local:[{agent_id,role,capabilities}], remote:{endpoint:{agents:[...]}}, self:{agent_id}}`。
- 用途：确认目标 agent_id 后调用 `request_collaboration`。
- 注册：Core Tier，`blocking=False`。

### 7.2 `request_collaboration`
- 签名：`request_collaboration(target_agent_id, task, timeout=None, wait_for_response=True)`。
- 语义：向平级 agent 发起**一次性协作请求**（channel=main_session）并**阻塞等待精简结果**（截断到 `max_result_chars`）。
- handler 内部：timeout 钳制 `min(timeout or default, max_timeout)`；防自协作（target==self → 报错）；生成 `collab_id=main_{uuid}` + `message_id`；构造请求；本地镜像；`call_all_endpoints("collab_message", params)` 广播；`_wait_for_response` 轮询本地镜像；摘要截断；cancel_event 检查；完成后写 `type=end` 归档。
- 注册：Core Tier，`blocking=True`（走 to_thread）。
- subagent 预留：`mode` 参数或独立工具留待未来（真正的 subagent = 更命令式的完整任务委托）。

## 10. 边界与安全

1. **单实例不影响主会话**：`enabled=false` 零影响；`enabled=true` 单实例（无对端）时 list 空、request 干净报错。
2. **A2A 前提**：依赖 a2a.enabled + 对端可达；不可达时 timeout 内返回干净超时文本。
3. **阻塞取消**：cancel_event 经 to_thread context 拷贝进线程，轮询 0.5s 检查；max_timeout 有界终止。
4. **结果摘要防膨胀**：max_result_chars 截断；只回填最终响应。
5. **会话隔离**：main_* 走独立命名空间 + channel 分流，worker 协作逻辑不处理；主会话 history_buffer 不污染。
6. **防风暴**：幂等集 + message_id 跨实例去重 + `_llm_lock` 并发锁。
7. **安全**：A2A 字段白名单 + sanitize_path + rate limit + 非参与者丢弃。
8. **兼容性**：worker 协作平面完全不变；`to="*"` 讨论模式不受影响。

## 12. subagent 预留扩展说明

- `mode: peer`（当前）| `subagent`（未来）：真正的 subagent = 更命令式的完整任务委托，目标以更服务化的身份/口吻响应。
- 非阻塞扩展点：`wait_for_response=False` 时工具立即返回"已派发"，结果经工作台/主对话注入异步回收（需后续补充结果回收与主会话续接机制）。
- 工具级会话隔离：当前用 `tools_override` + contextvar 兜底，未来可按 session 前缀做真正的工具集过滤。
- 服务化响应上下文：`build_main_collab_system_prompt` 已按服务性口吻设计，subagent 模式直接复用。
