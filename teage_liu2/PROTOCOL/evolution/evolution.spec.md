# evolution 域规范（v1.0.0）

> 唯一契约源声明：本文档 + `evolution.schema.json` 是 evolution 域的语言无关规范。
> **定位**: evolution 不是与 types 平级的"独立协议域"，而是**横切属性**——它规定"其余所有域如何演进"（新增/变更/废弃/版本）。9 域中的 evolution 是其余 8 域的元规则。

## 1. 稳定面 vs 演进面

| 面 | 内容 | 策略 |
|---|---|---|
| **稳定面** | 快照/action 交互模型、事件流语义（三层）、生命周期语义、错误责任矩阵 | **冻结**（v1.0 起，改动 = major 版本 + 双版本共存过渡期） |
| **演进面** | hook/event/action 的**集合** | **永续开放**，经三阶机制演进 |

## 2. 三阶演进

```
第一阶: 自定义扩展点（不改协议即可用）
  Event.type → "custom:*"   # core 透传, 观测扩展可消费
  Hook.name → "custom:*"    # 扩展声明实现, core 通用触发点调用
  Action.op → "custom:*"    # 扩展间传递, core 记录+忽略

第二阶: semver 版本化（受控添加）
  protocol_version: "1.2.0"(semver)
  minor = 向后兼容添加（新 hook/event/action, 老扩展不声明不调用, 零破坏）
  major = 破坏性变更（双版本共存过渡期, core 与扩展互验版本）

第三阶: RFC 流程（防协议膨胀）
  新元素提案 → 评审"能否由现有 custom/组合实现"
  能 → 不升级, 留在 custom; 不能（新时机/新语义）→ 入 minor
```

**行为条款 V-1（未知元素宽容）**: core 对未知 type/op/hook 的策略 = 透传/记录，绝不崩溃。
**行为条款 V-2（版本协商）**: core 与扩展互验 `protocol_version`，降级兼容或拒绝（可读错误）。

## 3. core 演进自由度

- **实现层**（性能/存储/LLM 适配/序列化）: 自由演进，不影响协议；
- **语义层**（新 hook/event/action）: 走 RFC + 版本化；
- **新增钩子 = 新增触发点**: core 定义触发时机，扩展声明实现与否，老扩展零感知。

## 4. 行为套件随协议演进

协议级黄金用例集随协议演进——新增协议元素必须同时新增用例，否则不进协议。行为套件用途 = v1.0 冻结前提 + 新宿主实现验收门槛 + 协议-实现漂移的持续审计工具（维护归 evolution 域）。
